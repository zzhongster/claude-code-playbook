# 反模式：照文档给事件钩子配埋点——一个 matcher 永不触发，另一个把数据记成两倍

## 一句话结论

给一套你没写的事件系统加埋点时，**两类错的信号强度天差地别**：漏记表现为「某项零调用」，看着可疑还有机会被追查；**重复记表现为一个完全正常、只是翻倍的数字，没有任何异常信号**。而验收时你只会看「有没有数据出来」——两类错都能通过。唯一的解法是**配置之前先装一个 dump 探针，把真实事件 JSON 打下来看**，别读文档就动手。

## 场景

- 给 Claude Code / CI / 编辑器 / 浏览器扩展之类**你没有源码的宿主**配 hook、middleware、event listener
- 目的是统计「某件事发生了几次」「是人触发的还是程序触发的」
- 官方文档给了事件名和字段表，看起来照抄就行

## 踩坑经历

2026-08-05，给一个 8 人团队内部 monorepo 的 14 个协作工具（7 个斜杠命令 + 3 个 subagent + 4 个 shell 脚本）加使用埋点（卡号 TOU-71）。目标是区分 `human`（人手敲的）和 `agent`（CC 自己调的）——这个比例是整件事唯一的产出，因为「流程该不该改」取决于它现在是人在走还是模型在替人走。

按官方 hooks 文档 + 卡面给的抓法表直接配 `PreToolUse` 的 matcher，**三处会错，全都不报错**：

| | 照着配会怎样 | 实际是什么 | 错误的信号长什么样 |
|---|---|---|---|
| subagent 的工具名 | 文档只提 `Task` | 实测是 **`Agent`**，且 `subagent_type` 可能整个缺省 | 3 个 agent **全程零记录**——可疑，有机会被发现 |
| 命令的抓法 | `human` 走 `UserPromptSubmit`、`agent` 走 `PreToolUse: Skill`，两条各管一类 | 人手敲一次命令，**两个事件各触发一次** | **每次人工调用同时记出一条 `human` 和一条 `agent`**，人机比例直接翻倍。数字看着完全正常 |
| 客户端差异 | 只配 `PreToolUse: Skill` 就能抓到命令调用 | 有的客户端把 `/命令` **就地展开成 prompt，根本不产生工具调用** | 人手敲的命令 **100% 漏记**，而机器调的照常记——比例反向失真 |

第二行是这里真正的教训。**永不触发至少还留下一个「零」让人起疑；翻倍的数字什么都不留。** 如果没在配置前先看真实事件流，这套埋点会安安静静跑满一周，然后交出一份人机比例错一倍的报告——而这份报告的用途是决定要不要改流程。

第三行更阴险：它不是「少了一类数据」，而是**只在人这一侧漏**，机器那一侧完好。结论会精确地指向「这些命令基本没人手动用，都是 CC 在调」——一个恰好符合直觉、因而不会被质疑的错误结论。

### 顺带踩到的两个纯技术坑

**`while read` 会丢掉没有换行结尾的最后一段。** 解析命令行时把它按分隔符切段再逐段判断：

```bash
printf '%s' "$cmd" | tr ';&|()' '\n\n\n\n\n' | while IFS= read -r seg; do ...
#        ^^^^ 没有 \n，最后一段被 read 直接吞掉
```

后果是「命令行里只跑一个脚本」这个**最常见的场景 100% 漏记**，而「一条命令跑两个脚本」只漏后一个——于是零星有数据，看着像在工作。改成 `printf '%s\n'` 即可。

**这个 bug 是离线用例抓到的，不是读代码看出来的**，也不是活体测试抓到的——活体测试当时恰好跑的是两条命令连写，出了数据就以为通了。

**`paste -d` 只吃单字节分隔符**，直接给 `、` 会把中文人名截断成 `张中�王涛`。先用 ASCII 逗号连接再 `sed` 替换。

## 解法

1. **配置前先装 dump 探针。** 一行 `{ cat; echo; } >> /tmp/probe.jsonl` 挂到所有关心的事件上，跑几个真实动作，看清 `hook_event_name` / `tool_name` / `tool_input` 到底长什么样，再写正式配置。探针写进**本机 gitignore 的局部配置**（Claude Code 是 `.claude/settings.local.json`），不污染仓库。**成本十分钟，省下的是一周的错数据。**

2. **工具入参结构不必猜也不必查文档——历史调用里就有。** Claude Code 的 `~/.claude/projects/*.jsonl` 存着每次真实的工具调用：

   ```bash
   find ~/.claude/projects -name '*.jsonl' -mtime -30 | while read -r f; do
     jq -c 'select(.message.content) | .message.content[]?
            | select(.type=="tool_use" and .name=="Agent")
            | {name, keys:(.input|keys)}' "$f" 2>/dev/null
   done | sort | uniq -c | sort -rn
   ```

   本次输出直接给出了答案，还顺带暴露了「哪些字段是可选的」这条文档里没有的信息：

   ```
   50 {"name":"Agent","keys":["description","prompt","subagent_type"]}
    8 {"name":"Agent","keys":["description","name","prompt","run_in_background"]}   ← 无 subagent_type
   ```

   **只看一两个样本会得出「`subagent_type` 是必填」的结论。** 要统计频次，不要看样例。

3. **两个事件可能指向同一次动作时，先问一句「它们会不会都触发」。** 答案是「会」的时候必须去重。本次的做法是**会话内认领标记**：先到的那个事件记账并留一个标记文件，后到的认领到标记就静默跳过、认领不到才按另一类记。

4. **同一件事有多条抓法时，让它们互相兜底，而不是二选一。** 命令这一路两个事件都留着：会展开成 prompt 的客户端由第一个事件抓到，会产生工具调用的客户端由第二个抓到并被去重逻辑吸收。**没有哪一条单独是对的，合起来才对。**

5. **验收判据必须是「实测到了这条数据」，不是「配置写上了」。** 本次把 3 类对象 × 2 类触发方式的 5 种有效组合逐一实跑，其中 **3 类照文档配根本跑不出来**。

6. **埋点绝不能有能力挡住宿主干活。** Claude Code 的 `PreToolUse` hook **以退出码 2 会拦截工具调用**，还能靠 stdout 吐 `permissionDecision` JSON 拦截。所以：脚本任何路径都 `exit 0`（`set -uo pipefail` 但**有意不加 `-e`**），配置层再包一道独立的 `exit 0`，并且 `>/dev/null 2>&1` 把 stdout 那条隐性拦截路径也封死。验证方法是**把脚本副本强行改成 `exit 2`，确认包装层仍返回 0**。

7. **hook 脚本值得写离线用例。** 它跑在宿主进程里、每次调用都触发，活体调试代价高且不可重复。把事件 JSON 当输入、落盘结果当输出，纯函数式地测——本次 18 条用例，抓到了活体测试恰好绕开的那个 `read` bug。用例里必须有一条是「**喂垃圾输入也 exit 0**」。

   > **0808 追记，这套用例的第二个战绩。** 三天后给同一套埋点扩统计对象，工具名首次出现带 `/` 的形式（四个入口的 basename 全叫 `run.mjs`，只能用相对路径区分）。而去重标记是**拿工具名直接拼文件名**的——`sh:diff-budget/run.mjs` 里的 `/` 被当成目录分隔符，标记文件建不出来，认领永远失败。
   >
   > 两点让它很难靠肉眼或活体发现：**①这行代码一直是对的**，旧工具名里没有斜杠，是新功能给旧代码引入了新的失效条件；**②失效是单向的**——`agent` 照记，只有 `human` 记不到。数据里会有这个工具的记录，看着在工作，只是那一列永远是 0。而人机比例正是整件事唯一的产出。
   >
   > 用例从 18 条扩到 26 条，写完实现一跑就炸出来了。**扩统计口径时，先问一句「新的名字形态会不会撑破旧的存储形态」**——文件名、目录名、JSON key、URL 片段，都是这类隐式约束的藏身处。

## 数据支撑

| 项 | 数 |
|---|---|
| 照文档/卡面配会出错的地方 | 3 处，全部不报错 |
| 其中「零记录」型（有机会被发现） | 1 |
| 其中「数字翻倍/反向失真」型（无任何信号） | 2 |
| 离线用例 | 18 条，抓到 1 个活体测试绕开的 bug |
| 实跑验证的组合 | 5 类全部，其中 3 类照文档配跑不出来 |
| 从历史 transcript 捞到的 `Agent` 调用样本 | 58 次（50 带 `subagent_type` / 8 不带） |

## 适用范围

- **适用于**：给任何自己没写的宿主加 hook / middleware / event listener 做统计；尤其是要区分「人触发」与「程序触发」的场景——这类区分几乎必然涉及多个事件指向同一动作
- **也适用于**：宿主有多个客户端实现（CLI / 桌面端 / IDE 插件）且行为不一致时
- **不适用于**：统计自己代码里的调用（直接在函数入口打点即可，不存在事件重叠与文档漂移问题）

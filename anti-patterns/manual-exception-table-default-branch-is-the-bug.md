# 反模式：手工例外表兜数据缺陷，默认分支恰是出错分支——已知疑似缺陷项静默带病上线

## 一句话结论

一类数据缺陷只能人工逐项确认（这里：早期录音没录反复段），于是用一张硬编码「例外表」（`AUDIO_QUIRKS = { 曲名: {skipMeasures:[...]} }`）兜——**登记过的对，没登记的落进默认分支，而默认分支正是出错分支**。表没有「完备性护栏」：你明明已经圈出了一批疑似缺陷项，但只确认填了一条，其余挂着「待耳测确认」，就默认当正常处理、无任何报错，静默带病上线，最后靠用户偶然发现。

## 场景

- 一批数据里有个别缺陷，缺陷位置**不能从计数/元数据推断，只能内容级人工确认**（耳测、肉眼、听查）
- 代码用一张 `{ key: 特例参数 }` 的手工表来对这些特例走不同分支
- 表里没登记的 key **默认走「正常」分支**——而对缺陷项来说，「正常」分支恰恰是错的
- 你已经识别出「疑似缺陷集」（甚至写进了 TODO），但只逐个确认填了一部分，其余静默按「正常」上线

## 详细说明

### 踩坑经历（声伴 shengban.aimusic.art，走谱播放器，2026-07 → 2026-09）

谱面有反复（volta 1号/2号房子），但 5 首 MVP 时代手搓的曲子是**单遍录音、没录 1 号房子**：唱到反复前直接进 2 号房子（如大森林 29 小节后直接 31，跳过 30）。播放器 `score-engine.js` 的 straight 模式把记谱小节按 rank 贴到 MIDI 小节网格上——音频跳过的小节在光标侧没跳，**从该小节起整体错一格，后面全对不上**。

2026-07-05 就定位了这 5 首、并选定用引擎里的 `AUDIO_QUIRKS` 表兜（曲名 → 该跳的小节）：

```js
const AUDIO_QUIRKS = {
  '七月的草原': { skipMeasures: [35, 36] }, // 34 → 37（volta1 未录）
};
```

**但只填了七月一首**，data-issues 里留了一行 TODO：「待耳测确认后加 QUIRKS：大森林、我爱你中华、两地曲、曙色」。这行 TODO 挂了**两个月**——因为默认分支（表里没有 = 当正常）不报错、不告警，这 4 首就静默带病在生产跑着，直到 2026-09 用户练歌时耳朵听出大森林光标错位来报。

复现调查里绕的弯（都因为静态信号失效）：

- `repeat-parser` 本身**正确**（它假设反复被演奏、正确展开成 volta1 走一遍再 volta2）；bug 在「音频根本没走反复」与引擎默认分支的错配，不在解析器
- 三种静态信号**全部分不开好坏**：① MIDI 小节数 vs 记谱数（噪声大，很多曲 66 vs 39）② MIDI 时长 vs 音频时长（全吻合 ±1s，因为谱面时序 MIDI 是 warp 到音频的）③ volta1 在 MIDI 里是否被压成 0 秒（已确认有问题的曲子 ratio 也≈1.0）。**真相只在音频波形里**，本地静态文件测不出，且线上走 API 从 OSS 取数、本地 `data/` 未必等于线上

### 破局：用「录入序号」当批次年代信号 + 已知正确样本验证提取法

- 静态信号失效时，**数据的录入序号（`song-index.json` 的 `id`）编码了录制批次/年代**。用户说「就是最早那批约 10 首」→ 把 id≤10 与「有 volta」交叉，一次锁定完整疑似集（大森林 id2 / 两地曲 id3 / 曙色 id5 / 我爱你中华 id6，+ 已修的七月 id1）。无 volta 的早期曲（秋水长天/望乡词/漫步街上…）天然没这问题，直接排除
- **用已知正确的样本验证提取方法**：线上生效的七月 `skipMeasures:[35,36]`，正是「XML 里 1 号房子范围 `[v1 … v2-1]`」（volta1@35、volta2@37）。用它反验证「XML volta 范围 → skipMeasures」这个提取法是对的，再批量套到其余 4 首，逐个交给用户耳测拍板

最终这 4 首用户 2026-09-13 全部耳测确认，`skipMeasures` 从 XML 可靠生成：大森林 `[30]`、两地曲 `[24…31]`、曙色 `[35…44]`、我爱你中华 `[40,41,42]`。谱面时序 MIDI **本身已跳过 volta1**（大森林谱51/MIDI50），所以前端补表这一处就够，不用再动数据。

## 适用范围

- 适用于：任何「个别数据有缺陷、只能人工确认、用硬编码例外表兜」的场景——媒体对齐特例、OCR/转写修正表、地名/别名映射表、单店特判参数……
- 核心教训（两条）：
  1. **例外表的默认分支不能是「当正常」**——对缺陷项而言默认分支往往就是错的。要么让未登记的**疑似缺陷项显式报警/挡下**（如：断言「每首有 volta 的曲子，要么音频已展开、要么在 QUIRKS 表里」，缺一个就 CI 红/启动报错），要么把判定**程序化**（音频↔乐谱对齐残差自动定位缺录段），别靠人肉补表
  2. **「待确认」的 TODO 等于「已知带病上线」**：你圈出了疑似集却让默认分支放行，就是主动选择让没确认的那些静默错着跑。识别出疑似集的那一刻，默认就该 fail loud
- 方法论副产品：静态信号测不出时，**数据的录入/自增序号常编码生产批次年代**，是缩小排查范围的强信号；**先用一个已知正确的样本验证你的提取/推断方法，再批量套用**

# 反模式：把「已经有人核过一轮」的表当事实输入，只补空白

## 一句话结论

客户给的名单里「规范公司名」「官网」「关键人」这些列已经填好了，很容易只去补空着的格子。但手工核过一轮的数据**本身就有错、而且会过时**：公司配错、联系人离职、负责人换人。把它当事实，后面所有找人、取数、验证都建立在错的地基上，还要为错的公司付钱。**原表的每一列都是待核数据，按和空白一样的标准重新核。**

## 场景

- 客户 / 同事交来一份「已经核过」的名单，要补联系方式
- CRM 导出的历史客户（几个月到几年前录入）
- 上一轮自动化 / 外包的结果被当作下一轮的输入

## 踩坑经历（2026-10-19，水务展会观众名单 67 家）

原表带「规范公司名（核实后）」「官方网址」「关键人/职位」「邮箱」「电话」，有人手工核过。重新核了一遍：

| 原表那一列 | 实际 |
|---|---|
| 公司核实 | 16 家「未核实」里 **6 家是原表配错**：伊拉克净水公司判成德国公司、汽修店当成水务公司、猎头公司当成水务公司、美国同名公司…… |
| 关键人 | 原表 66 人：在职 22、**已离职或履历里没这家 9**、查不到 35 |
| 总经理 | 一家供水公司原表写的总经理**已卸任**，官网现任另有其人 |
| 规范名 | 后续企业库匹配时把原表规范名也拿去匹配，**又把已更正的公司配回了原表那家错的**；显示名也沿用了错的 |

如果只补空白：会去给汽修店、猎头公司找「水务采购负责人」，给已离职的人取邮箱电话（按条付费）。

## 怎么做

1. **原表每一列都打上「待核」**：公司身份、官网、人名，与空白格同一套核验标准（官网体检、企业库、海关提单、在职核验）
2. **原表不对的不删，标出来**：「核实结论 = 已更正原表」「在职核验 = 已离职」，让读表的人看得到变化
3. **更正过的行，下游一律用更正后的值**：企业库匹配、显示名、搜索词都不能再回读原表那一列（这次就是回读导致配回错公司）
4. **保留原表的人，但不让未核验的人冒充已核验**：交付表里「原表已有·未核验」和「已核验在职」分开标

## 为什么容易犯

- 填好的格子看起来「已完成」，注意力自然只给空白
- 「别人核过」被当作免责：出错了是原表的问题
- 重核要花时间，补空白更快出数

# 反模式：算「改这份共享文件要付多少代价」时只算自己这一刀，没看同批兄弟任务——而它们本来就要改同一份文件

## 一句话结论

一份被多张卡共用的受管文件（评审判据册、token 真源、共享配置），改它往往带一笔**显式代价**（评测成绩作废、要重跑一轮考试、要拉人批准）。看到这笔代价就决定「本刀不改、攒批」之前，必须先问一句：**这笔代价是不是反正会被同批的别人付掉？** 若是，我这一刀的**边际成本为零**，延后换来的只有「文件与真源不一致」这段窗口。

推论一：**机器脚本答不全这个问题。**「谁在动这份文件」的扫描只看得见**已经改到那几份文件**的人；同批的卡可能已经开工、已经改了别的文件，照样显示 0。
推论二：**问这份文件的使用者（agent / 工具）不构成核验。**它答得了「这个改动影响不影响我判断」，答不了「别的卡上有没有要求同刀改」。

## 场景

- 一批并行的子任务同改一个真源（设计 token、schema、规则表），且各自都要顺手更新同一份「规则 / 判据 / 文档副本」；
- 改那份文件有一道**可量化的惩罚**：评测连续达标计数清零、要补跑 N 次考试、进入需要人批准的路径；
- 工具链里有 hook 或脚本，在你即将碰它时提醒「改它会清零 X」；
- 于是很自然地判断：「这次只是个括注，攒批一起改更省」。

## 踩坑经历

TOUCH 2.0，2026-09-17，界面改版的三张并行子卡（C1a 颜色 / C1b 字体 / C1c 圆角）同改 `packages/design-tokens/tokens.json`。

C1c 把圆角三档从 8/12/16 改成 6/10/14 之后，评审用的判据册 `.claude/agents/design-token-auditor.md` 里还写着旧值。PreToolUse hook 出声：

> ⚠️ 你正要碰红队清零面：[判据册] design-token-auditor.md ⇒ 改它会按口径第 8 条清零这几卷：ui-token。每清一卷 = 欠一轮 9–15 次开考。

我据此判：括注而已，判据册真正判的是 token 名不是数字 ⇒ **本 PR 不改，攒批到改版期别的判据册改动一起改**，并把这个判断交给 design-token-auditor 复核，它也认了「可以攒批改」「不需要同 PR 改」。

**冷审（干净上下文子 agent）翻出兄弟卡 C1a 的卡面**，上面 14:22Z 就有一条评论：

> 判据册的规则表**本卡改 `tokens.json` 的同一个 PR 里一起改掉**——早于 token 改，auditor 会按新值去判旧实现；晚于 token 改，auditor 会按旧值把本卡判红。

而 C1a 当时正在改同一份判据册（改的是色值段）。⇒ **那一卷无论我改不改都要清零**，我这一刀的边际开考成本是零。改判，同 PR 改掉，代价写进 PR 描述：「合入即作废该卷现行达标记录，重跑等两卡都合入后一次跑」。

### 第二层：想用脚本补救，脚本也答不了

我最初想把教训写成「跑 `whos-touching.sh` 看有没有别人在动」——**那条处方是错的**，时间线上它救不了这次：

| 时刻 | 事件 |
|---|---|
| 14:22:58Z | C1a 卡面出现「同 PR 改判据册」那条评论 ← **唯一在决策前可见的信号** |
| 15:24Z | C1a 会话开工（卡置 In Progress、建分支） |
| 15:26:50Z | C1a 已改 `tokens.json`（85 个值，未提交） |
| **15:28:02Z** | **C1c 跑扫描脚本：「扫了 26 个工作区，其中 0 个在动高冲突面」** ← 我在这一刻做了延后的决定 |
| 15:36:03Z | C1a 首次改判据册 |
| 15:48:51Z | C1c 第二次跑同一脚本：显示 1 |

脚本不是「没扫到已开工的卡」，是它**只比那几份会触发清零的文件所在的目录**（`tools/redteam/`、`.claude/agents/`）。C1a 已开工、已改真源，只是还没改到判据册 ⇒ 显示 0 是**正确输出**。

⇒ **「谁会改这份文件」是意图问题，只有卡面/ticket 答得了；扫描答的是「谁已经改了」，而且只代表跑的那一刻。**

## 正确做法

1. **动多卡共用的受管文件之前，按母卡的子卡清单逐张扫一遍卡面评论**——不只读本卡与母卡。一次查询的事，而这次它是唯一能救的信号；
2. **算代价时先问「这笔罚款是不是反正有人要付」**：若是，本刀边际成本为零，延后只剩坏处（真源与规则表不一致的窗口）；
3. 扫描脚本当**补充**不当**依据**：它看得见的是已发生的改动，且限于特定目录；做决定前重跑一次，但别拿它替代读卡面；
4. **别把「问这份文件的使用者」当核验**：被问的 agent 答的是「这影响不影响我判断」，不是「别人有没有要求同刀改」；
5. 真要延后，落点写在**那张会改它的卡的卡面**，并在 PR 描述写明代价——不写就等于没人知道有笔待付的账。

## 数据支撑

- 同批 3 张卡共用 1 份真源 + 1 份判据册；延后方案的「省一次清零」实际收益 **0**（同批另一张卡本来就要清零同一卷）；
- 决策时唯一可见的正确信号出现在决策前 **66 分钟**，在兄弟卡的卡面评论里；
- 机器扫描在决策时刻显示 0，**20 分钟后**才显示 1。

## 适用范围

- 适用于：并行子任务共用真源 / 规则文件；改动带可量化惩罚（评测清零、重跑、需批准）；有「谁在动它」的扫描工具；
- 不适用于：只有一个人在动那份文件；惩罚不可量化或不存在（那就直接改）。

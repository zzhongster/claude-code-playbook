# 反模式：把「结果断言」读成「实现机制」，于是两份规格看起来在打架

## 一句话结论

规格里有两种句子：**给形状的**（这个字段默认值是 X、这个端点返回 Y 前缀）和**给结果的**（重复调用不产生新行）。前者不可变形，后者往往在**多种机制下都成立**。当一份规格给形状、另一份给结果，看起来像冲突时，**先问那条结果断言是不是在两种机制下都成立**——若是，它本来就没规定机制，不构成冲突，也不需要上级裁决。

推论：**「两份文档同档，裁决顺序帮不上」这个判断本身要先验证一次。**同档不等于同类，形状与断言撞车时断言让路。

## 场景

- 规格分册化（数据模型、API 契约、阶段验收各一册），同一件事在多册被从不同角度提到；
- 验收条目写成「Given…Then…」，括号里顺手带一句当时设想的实现机制；
- AI agent 或新人开工时撞上「A 册这么说、B 册那么说」，按纪律停下来等裁决；
- 上游已有实现照其中一种读法落了地，于是「改规格」与「改代码」都显得代价很大。

## 踩坑经历

TOUCH 2.0，2026-08-15。审批流的卡开工时撞上「一行记录到底何时 INSERT」：

| 出处 | 句子 | 类型 |
|---|---|---|
| 数据模型 §2.8 | 该列默认值 `draft`；`operation_id` 的「铸造时机：草稿生成时」 | **形状** |
| API 契约 §5.5 | `POST /campaigns/{id}/start` = 「开始批量生成草稿，进入审批队列」；草稿列表返回该表的 ID 前缀 | **形状** |
| 阶段验收 P4-T04 ③ | 「同一 campaign 重复 approve **不产生新**记录（唯一键拦下）」 | **结果断言** |

负责的同事把它定性为「三本同档分册互相打架，裁决顺序帮不上」，停下等裁决——**定性错了**。第三条是否定断言，它在两种机制下都成立：

- 机制甲（approve 时 INSERT）：靠唯一键拦下第二次 → 成立；
- 机制乙（行先存在，approve 是 UPDATE）：**根本不 INSERT** → 自动成立，且更强。

括号里那句「唯一键拦下」是当时设想的机制，不是要求。**真正预设了机制甲的不是规格原文，是上游照这个读法写的代码。**于是「规格 A vs 规格 B」的死结，实际是「一份实现选了一种已被形状排除的读法」——那不需要裁决谁对，只需要核一遍哪条句子给的是形状。

### 第二层：同一次里，代价评估也是从措辞推断的

同一条评论里还有一句：「这要动上游已合入 main 的代码，属受管路径且是别人刚合的卡，所以不自行动手。」

一条命令就能证伪：

```bash
git grep -ln "enqueueDispatchJob" origin/main -- '*.ts'
```

五个文件命中，**没有一处是真调用**——四处是注释里提到函数名，一处是模块导出。要改的是一个**还没有任何调用点**的函数。「别人刚合的卡」是真的，「动它风险大」是从这个措辞推出来的，没核过。代价被高估之后，本可以只停一刀，结果整张卡停了半天。

**两处根因相同：从文本措辞推断，没去核实物。**一处推断的是规格意图，一处推断的是代码耦合。

### 第三层：改完模型，旧代码里的「理由注释」可能要反向重写

原实现有一段注释解释为什么把 INSERT 和取额包在同一个 savepoint 里：取额失败必须让那行消失，否则它占住确定性幂等键，「一封从没发出去的信永久占住一个位子，且不报错」。

模型改成「行在草稿生成时建、审批时取额」之后，这条**方向要反过来**：取额失败时**绝不能删那行**——它是用户正在审批队列里看着的草稿，删掉就是「点了批准，草稿凭空没了」，同样不报错。**同一个形状的病，相反的处方。**照抄旧注释必踩。

裁决只说「取哪个模型」是不够的，**必须点名哪些既有理由在新模型下失效**——理由注释写得越好，越容易被原样保留。

## 替代方案：三问判别法

撞上「两份规格打架」时，按顺序问：

1. **这两条句子分别是形状还是结果？** 形状 = 默认值、枚举、ID 前缀、端点入参/返回、字段何时铸造；结果 = 「不产生」「不重复」「最终一致」这类可被多种机制满足的断言。**只有形状与形状相撞才是真冲突。**
2. **那条结果断言在对方的机制下成不成立？** 成立 → 没有冲突，重述它的机制即可，不必推翻验收条；
3. **代价评估里的每一句「要动 X」，跑一条命令核过没有？** 调用方数量、diff 行数、谁批——全是可测量的，不要从「那是谁的地盘」推断。

裁决落盘时，除了结论，还要**逐条核旧模型下的硬门在新模型下是否削弱**（本例四条硬门逐条核过，三条与 INSERT 时机无关、一条变强），并**点名哪些既有注释/文档的理由需要反向重写**。

## 适用范围

- 适用于：多册规格、多方实现的项目；把「停下来问人」写进纪律的 AI 协作流程（纪律是对的，但停之前要先把定性做对）；任何验收条目写成「结果 + 括号里的机制」的地方；
- 不适用于：两条**形状**真的互斥时（那是真冲突，该裁决就裁决）；规格与代码现状冲突（那是另一类问题，代码让路）。

**写规格的一侧也有一条**：结果断言里别顺手写机制。要写就写成「本条只断言结果，不规定实现时机」，或者干脆把机制单列一句。一句话没写清，代价是下游一次误定性加一次阻塞——而且**下一个人还会这么读**。

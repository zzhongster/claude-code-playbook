# 反模式：黄金集的负例是按另一个问题标出来的

## 一句话结论

关联（把样本名挂到登记库记录）的黄金集负例，如果拿去重的 prompt 去打标（"这两个名字是不是同一家公司"），同名异城的落选候选会被标成 SAME——标签回答的不是关联问题。结果是负例只剩 7 个，错关联率无法计算，比选报表全是"样本不足"。每种判定任务要有自己的 system prompt 与缓存命名空间，黄金集按 `kind` 分别打标。

## 场景

- 同一个 `Judge` 既做去重 T4 判定，又做 S4 的候选关联判定，也给黄金集打标
- 关联黄金集的负例 = 规则层因城市不符而落选的候选

## 踩坑经历

2026-08-30 企业样本去重 Task 16：link 黄金集 1,125 对，Opus 5 打标 SAME 1,073 / DIFFERENT 7。追查发现打标 prompt 是去重的；关联的问题应是"B 这条登记记录是否就是 A 这家登记主体"，同名不同城在中国是不同法人。加了 `SYSTEM_PROMPT_LINK_V1`、`PairInput.kind`、缓存键 `{pv}-link` 后重标。

同一天去重侧也遇到口径问题：DeepSeek 对"同集团不同法人"（`HISENSE IMP&EXP` vs `HISENSE INTERNATIONAL`、分公司 vs 总公司）判 SAME，错并率 4.9%；把口径写进 prompt v2（同一登记法人；职能词/集团/分公司/异地括号 → DIFFERENT；存疑 → UNSURE）并用同一 prompt 重标黄金集后，错并率降到 1.0%。**标签与模型必须用同一份口径**，否则比的是口径差异不是模型质量。

## 正确做法

- 每类判定一份 prompt、一份缓存命名空间；`PairInput` 带 `kind`
- 黄金集抽样时负例要真的是"该问题下的负例"（关联：同名异城/落选候选；去重：不同法人）
- 比选报表打印每类的 n、n_neg，负例低于阈值直接判不通过
- 口径决定（分公司、集团成员）是产品决策，先问人再写进 prompt

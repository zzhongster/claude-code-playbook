# 反模式：凭「页面上出现了公司名」认定是这家公司的官网——零售商、平台、目录页全会通过

## 一句话结论

给一家公司找新官网（旧域名失效）时，把「候选网站页面上出现了公司名」当身份核对，误配率过半：**卖它产品的零售商、电商平台、企业目录、新闻报道、同名的别国公司，页面上都有这个名字**。这是典型的「必要条件当判据」——页面有公司名是必要的，远不充分。真正能区分的是：候选**域名本身**是否含公司名主体词、目标国家信号是否吻合、站点类型是否根本不可能是官网。

## 场景

- 名单里的官网域名失效了（打不开 / 不收信），要自动找到它现在的官网
- 候选来自：同名换后缀（`.com` ↔ `.es`）、搜索「公司名 + 国家」的前几条结果
- 找到的新域名会被拿去**继续查人、挖邮箱**——配错一个，下游就带出一串错公司的人

## 踩坑经历（2026-10-04，164 家失效域名）

第一版核对规则：候选页面含公司名过半主体词，且（同名换后缀，或页面有完整公司名 + 国家信号）。跑完找到 47 个新域名，逐条人工复核，**27 个是错的（57%）**：

| 名单域名 | 配到 | 为什么会通过 |
|---|---|---|
| `baitpop.com` | `tacklewarehouse.com` | 零售商在卖它的产品，页面满是品牌名 |
| `thecupandmugcompany.com` | `made-in-china.com` | 电商平台，什么词都有 |
| `tbcthebestcrafts.com` | `diyncrafts.com` | 手工博客，"best crafts" 是常用词 |
| `empresite.eleconomista.es` | `eleconomista.es` | 名单登记的本来就是企业目录页；"还原主域名"后变成一家报社，**还从报社带出 3 个员工邮箱** |
| `4ainternacional.com` | `ntv.es` | 原站跳转到了主机商默认页 |
| `americanheritage.ph` | `americanheritage.com` | 菲律宾公司配到同名美国公司——"同名换后缀"被当成强证据 |

最危险的是有人的那几条：错配的域名照样能查出员工、挖出邮箱，结果混进交付名单，**格式全对、来源可查，就是公司不对**，下游几乎不可能发现。

## 收紧后的判据（复核后 27 个全部剔除）

1. **站点类型否决**：电商平台、媒体、企业目录、主机商、博客一律不能当官网；名单域名本身是这类站点的，单独标出
2. **换了主名的候选，域名本身要含公司名过半主体词**——零售商/平台/博客的域名不会含（`tacklewarehouse` 不含 bait/pop）。这是区分力最强的一条
3. **同名换后缀也要国家信号**：新后缀就是目标国后缀，或页面写了国名。"同名"只说明名字一样，不说明是同一家
4. **原站自己跳转过去的**可放宽（跳转是域名所有者设的），但仍要核对落地页有公司名，防跳到主机商/停放页

代价：几家大概率正确的也被拒了（`mollymy.se` → `.com`、`waterbottleshop.co.uk` → `.com`，新站没写国名）。在「找到的域名会被拿去取人」的场景里，**宁缺勿错**是对的取舍：漏一家只是少几行，错一家是往名单里注入错误数据。

## 怎么避免

- 写身份判据时先问：**哪些不是这家公司的页面，也会满足这个条件？** 列出来（零售商、平台、目录、媒体、同名公司），逐个确认判据能把它们挡掉
- 自动找到的映射，**上线前按判定类别各抽样人工复核**；第一版误配率这么高，靠抽样十几条就能发现
- 把"判定依据"随结果落盘（这次每条都记了 `evidence`），复核时一眼看出是哪条规则放进来的

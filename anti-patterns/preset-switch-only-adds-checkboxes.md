# 换预设 / 套餐时只勾不取消：上一个套餐的收费项悄悄留下

## 一句话结论

表单上的「套餐 / 预设」按钮如果只把新套餐要的项勾上、不取消上一个套餐勾的项，那么从大套餐换到小套餐时，大套餐里的收费功能会原样留着，而页面提示写的却是小套餐。正确做法是：**每次换套餐都从「基线」重算**——基线是页面打开时的现值（已有客户 = 账本里已开通的；新客户 = 全不勾），结果 = 基线 ∪ 新套餐的项。前端填值和服务端回填必须是同一个函数、同一个口径。

## 场景

- 后台开通单 / 下单页有一排「套餐」按钮，点一下把额度、有效期、功能开关一次填好，提交前还能逐项改。
- 套餐的授权语义是「至少要有这些」（不能把客户已有的功能关掉），于是很自然地写成「把套餐里的项勾上」。
- 某些角色低于审批阈值可以直写（不经第二人复核）。

## 详细说明

trade-agent-data 运营后台（2026-10-28，PR #202）把套餐按钮从「服务端重渲染」改成「前端填值、不提交」时写成了：

```js
p.ents.forEach(v => boxes.forEach(c => { if (c.value === v) c.checked = true; }));
```

复现路径：新客户页默认选中「标准开通」（四项功能全勾，含收费的联系人详情）→ 改点「14 天试用」→ 四项仍然勾着，但提示写「已选 14 天试用」、`template` 也是 `trial14`。审批人提这张单时，100 点低于审批线，单子直写生效，收费功能就这么没人复核地开了出去。

同一个 PR 里还暴露了第二个问题：前端、PC 服务端回填、手机服务端回填三条路径对「套餐没管的字段」各有一套处理（有的清空、有的保留、有的只清一部分），三种口径。

修法（dba801dd）：

1. 页面内嵌的数据块带上 `__base`（基线授权）。
2. 点套餐：先把所有勾选框重置为「基线 ∪ 新套餐授权」；套餐管的那几栏先清空再填。点「不选」：那几栏清空、授权回到基线。
3. 服务端抽出唯一的 `apply_preset_values(values, preset_id, today, base_ents)`，PC 与手机的回填分支都调它；前端脚本照着它实现，单测钉住「标准 → 14 天试用 只剩 playbook」。

## 为什么容易犯

- 「预设是至少要有这些」这句业务规则，被直译成了「只勾不取消」，忘了这条规则说的是相对**客户现值**，而不是相对**上一次点的套餐**。
- 改成前端交互时，服务端原来的「每次从现值重算」被丢掉了，没人对照两边的口径。
- 测试只测了「点一个套餐后字段对不对」，没测「连点两个套餐」。

## 适用范围

- 适用于：任何「一键填充、可再修改」的表单预设——套餐、模板、权限包、价格档位，尤其是包含收费项或权限项的。
- 不适用于：预设本身就是「覆盖成恰好这些」的语义（例如角色模板直接替换全部权限），那种情况重算基线就是空集，只是同一规则的特例。

# 反模式：质量闸门只检查总样本数，不检查分母

## 一句话结论

"错并率 ≤ 1% 才能上线"这种闸门，分子是"标注 DIFFERENT 但模型判 SAME"，分母是**负例数**；只要求"总样本 ≥ 1000"挡不住"990 条 UNSURE + 9 条 SAME + 1 条 DIFFERENT"——分母 1，错误率只能是 0 或 100%，模型在那一条上答 UNSURE 就拿到绿灯。每个比率型指标都要对**它自己的分母**设下限，并把分母打印在报表里。

## 场景

- 黄金集由 LLM/人工打标，标签含 UNSURE，负例占比事先不可控
- `compare_models` 输出 `false_merge_rate` 与 `pass`，上线决策只看 `pass`
- 第一版已经修过"空子集 0/0 不能算通过"，以为够了

## 踩坑经历

2026-08-29 企业样本去重 Task 13。我在 dispatch 里专门要求 `MIN_SAMPLES={"dedup":1000,"link":500}`、不足即 `pass=False`。评审指出下限只作用于 `len(sub)`，负例数 `n_neg` 只在返回 dict 里、不进 markdown 表——人看报表根本看不到分母有多小。修法：`MIN_NEG={"dedup":100,"link":50}` 独立门槛（测试可覆写），`n_neg` 进表；顺带把 `agreement`/`unsure_rate` 在无标注时改成 `None` 而非 `0.0`，同一个"0/0 读成真实数字"的坑。

## 正确做法

- 每个比率一个下限：总量、负例、正例分别设阈值，任一不足就 `pass=False` 且 rate 为 `None`
- 报表列出全部分母（`n`, `n_labeled`, `n_neg`），让人能一眼看出"1/1"
- 无法计算时输出 `None`，不要输出 `0.0`——0.0 会被当成"零错误"
- 测试要覆盖"总量达标但负例不足"这一格，而不只是"总量不足"

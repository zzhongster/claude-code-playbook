# 反模式：批量替换脚本断言中途失败，后面的检查却对着旧文件报"通过"

## 一句话结论

用"读入 → 逐条 `assert old in s` → `replace` → 最后写回"的脚本批量改文件时，任意一条断言失败，**整批改动都不会写回**。如果后面接的是 `;` 或换行而不是 `&&`，下一条检查命令会对**原样未改的文件**报"通过"，失败就这样被掩盖了。正确做法：先对所有模式做预检，一次性列出全部未命中项；命令一律用 `&&` 串起来；写回后断言新文本确实存在。

## 场景

- 让模型用 heredoc 里的 Python 一次改多个文件、几十处字符串（改报告措辞、改配置值、改代码里的常量）；
- 替换模式是从 grep 结果里手抄的，常常带了多余的前缀（行首的 `[`、引号），或者把同一段文字在不同文件里的写法当成一样；
- 脚本后面紧跟着"重新生成 + 检查"。

## 踩坑经历（2026-11-23，三份报告的批量更正）

**第一次：** 修正附件里的 10 处合计数字。第 10 条模式写成了 `["Arctic SA(Arçelik)",…`，而实际文本是 `["欧洲","Arctic SA(Arçelik)",…`，前缀多了一个 `[`，导致断言失败。整段命令是：

```bash
python3 - <<'EOF'
...  # for a,b in rep: assert a in s; s=s.replace(a,b)
open(p,'w').write(s)
EOF
python3 build/market.py && python3 check.py market.json
```

heredoc 和下一行之间是换行，不是 `&&`。输出里先是 `AssertionError`，紧接着是 `通过`。前 9 条也都没写回去，因为写回在循环之后。那个"通过"检查的是旧文件，很容易让人以为修好了。

**第二次：** 按审阅意见一次改 3 个文件、约 30 处，每个文件调用一次 `patch()`。第一个文件全部命中并写回；第二个文件有一条模式开头多带了一个引号，断言失败，于是第二个文件一处没改，第三个文件根本没执行。结果是三个文件处于三种状态：已改、未改、未执行。只能靠 grep 逐个确认哪里改了，再把剩下的部分去掉坏模式后重跑。

## 根因

1. **原子写回和"边改边断言"混用。** 写回放在最后，是为了单文件内的原子性，这本身没错。但断言失败时只抛异常，不报告还有哪些模式也没命中，修一条、跑一次、再撞下一条。
2. **多文件之间没有原子性。** 每个文件单独写回，失败点之前的文件已经变了，之后的没变，状态被切开了。
3. **用 `;` 或换行串命令。** 前一步失败不会阻止后一步，后一步的成功输出覆盖了前一步的失败信号。
4. **模式从展示截断的 grep 输出里抄写。** `cut -c1-200` 截断后看不到完整前后文，抄的时候多带或少带一个字符。

## 正确做法

```python
def plan(path, reps):
    s = open(path).read()
    bad = [(a[:60], s.count(a)) for a, _ in reps if s.count(a) != 1]
    return s, bad

jobs = {"haier.py": [...], "market.py": [...], "peer.py": [...]}
staged, errors = {}, []
for p, reps in jobs.items():                    # 第一遍:只预检,不写
    s, bad = plan(p, reps)
    errors += [(p, *b) for b in bad]
    staged[p] = (s, reps)
if errors:
    for e in errors: print("未命中或不唯一:", e)   # 一次列出全部问题
    raise SystemExit(1)
for p, (s, reps) in staged.items():             # 第二遍:全部通过才写
    for a, b in reps: s = s.replace(a, b)
    assert all(b in s for _, b in reps)          # 写回前确认新文本都在
    open(p, "w").write(s)
```

- 断言的是 `count == 1`，而不是 `in`，这样同时防住"没命中"和"命中了不该改的地方"。
- 外层命令一律用 `&&`：`python3 patch.py && python3 build.py && python3 check.py`。
- 改完用 grep 计数复核旧措辞：`grep -c "旧措辞" *.py` 应为 0。
- 模式尽量取能唯一定位的**最短**片段，不要带行首的括号和引号。

## 适用范围

- 适用于：模型或脚本对多个文件做字符串级批量修改，后面紧接生成、检查、提交的流水线。
- 不适用于：改动走结构化 API（JSON 按键改、AST 改写），或一次只改一处、改完人工看 diff 的场景。

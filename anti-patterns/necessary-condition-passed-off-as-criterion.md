# 反模式：把必要条件当验收判据——判据"升级"一次，往往只是换了个更严的必要条件

## 一句话结论

验收判据里凡出现「非空 / 有返回 / 不报错 / 能解析 / 数量 > 0」，它多半是**必要条件**而不是判据；而当第一次被证伪、你把它收紧一档之后，**新判据通常仍然是必要条件**——因为真正要回答的问题（够不够用）没有便宜的观测量，而每次挑判据时最先想到的还是"怎么查"。同一个验收连着两次栽在这上面，是常态不是意外。

## 场景

- 决定一个外部工具/数据源/接口**要不要接进主流程**，判据由你写
- 上游修好了你上次指出的问题，你要复验
- 判据能写成一行命令（`len(data) > 0`、`dig +short`、`HTTP 200`），而"能不能支撑用途"要靠抽样比对真实答案

## 踩坑经历（2026-08，供应商工具选型）

要判断一个"按公司名查官网"的工具能不能进研究 Agent 的工具白名单。用途明确：给 Agent 定位企业官网、给"按公司名找联系人"那步收窄匹配范围。

**第一版判据**：上游把 key 开通后，写下"实测**返回非空**即可加入白名单"。

实测确实非空——返回的是 `_<32位hex>_.com` 这样的哈希伪域名，DNS 查无记录（上游对未收录公司返回的占位值，见 `patterns/upstream-placeholders-need-your-own-gate`）。**非空 ≠ 有效。**

**第二版判据**：上游修好占位过滤后，我把判据升级为"抽样 ≥10 家已知有官网的公司，返回的 domain **有 DNS 记录**且与目标公司相符 ≥80%"。看起来严实多了——有样本量、有可自动化的正确性断言、还引了上一次的教训。

重跑 10 家结果：占位符零泄漏 ✅，DNS 可解析 **3/3 = 100%** ✅。**但召回只有 3/10，且命中的三条没有一条是主域名**——一个国别顶级域子站、一个子品牌二级域、一个区域站。Agent 拿到国别子站会把某国分公司当成集团本身，作证据来源也是错的层级。**有效 ≠ 够用。**

两次判据都不是推错：非空是必要条件，DNS 可解析也是必要条件。**错在把必要条件当成了判据本身**——而必要条件恰恰是最容易写成一行命令的那部分。

最后的结论是不接这个工具，理由从"它返回假数据"（第一次）换成"它的覆盖面不匹配用途"（第二次）——**两个理由要分开记档**，否则上游哪天提升了收录率，会有人以为这条否决还成立。

### 值得单独记的一层：说得出这条纪律，不等于会用它检查自己

这两次都发生在我**正在以"判据选错观测点"为由挡别人 PR** 的同一段时间里：同一天我在一条 PR 上写下"验筛选器要枚举状态空间，不是跑一遍此刻的快照"，在另一条上引"门禁的验收是反例被拦住，不是装上了"，转头给自己的验收写了"返回非空即可"。

顺带的注脚：把这段经历写成文档提交时，**CI 的真实域名闸连拦两次**——第一次我把实测的真实域名原样写进了文档；第二次我"脱敏"成 `<品牌>-区域` 加顶级域的占位形态，闸从里面切出了一个真实存在的域名。**加尖括号不等于脱敏**，脱到不再是域名形态才算。一份记"判据不够"的文档，连着两次被同一道门用"你的判据不够"拦下。

## 解法

1. **先把"要回答的问题"写成一句人话，再挑观测量，然后显式问一句：这个量与那句话之间差了什么？** 本例两次的差值分别是"非空但内容假"与"内容真但层级错"，两次都能在写判据的当场问出来，成本是一句话。
2. **判据里出现"非空/有返回/不报错/能解析"就默认它是必要条件**：要么补上"且……"，要么明确承认这一轮只验到必要条件、把真判据挂到下一轮——**承认了也比误以为验过了强**。
3. **抽样类判据把样本一起定死**。"≥10 家已知有官网的公司"比"实测有效"强，不只因为更严，而是因为**别人能复跑、也能指出你样本选偏了**。本例第二版判据没救回我，但它让"为什么不够用"变得可讨论：召回 3/10 是个能贴出来的数字，"感觉不太行"不是。
4. **一次修正之后要再问一遍同样的问题**。判据被证伪时的自然反应是"把它收紧"，而收紧后的判据通常仍在必要条件那一侧——因为你还在同一个"怎么查"的思路里。**修正的正确起点是回到那句人话，不是回到上一版判据。**

## 适用范围

- 适用于：外部工具/数据源选型、供应商能力验收、接口联调的完成判据、任何"要不要接进主流程"的决策
- 不适用于：单元测试的断言设计（那里"必要条件"通常就是被测契约本身）

# 「实验证实 X 不发生」推广不到「什么都不发生」

## 一句话结论

受控实验的结论边界是**它实际测量的那个观测量**；把「实验证实触发 T 后 X 没发生」读成「触发 T 是安全的」，是把单观测量结论静默升级成了全称保证——同一个触发器上挂着的其他联动，实验一个都没排除。

## 场景

给自动化流程（issue 联动、CI 门禁、hook、webhook）做过一次受控实验、得到「加了防护 Y 之后坏事 X 不再发生」的结论后，团队把「加 Y」写进流程文档。此后所有人（包括 AI）按「有 Y 就安全」操作——直到同一触发器的**另一条**联动冒出来。

## 详细说明

### 踩坑过程

TOUCH 2.0 的归档流程天生要提「卡还没做完的 PR」。0807 做过一次干净的受控实验：两个相隔 15 分钟的 PR 对照，正文无魔法词的合并后 **2.8 秒**把 Linear 卡翻成 Done，写了 `Part of <卡号>` 的没翻。结论落进 `/pr` 与 `/archive` 文档：「正文写 `Part of` 即可解决：链接照挂，卡不翻 Done。」

0810 我按此操作：归档 PR 正文带 `Part of TOU-97`，合并。卡确实没翻 Done——但合并后 **2.7 秒**，卡从 In Progress 被推到了 **In Review**。当时卡上还挂着一个 OPEN 的 PR、还有一页没交付，看板上却显示「待审」。同日第二个补记 PR 合并，同一联动再次触发，机制坐实。

文档那句话本身是**准确的**（它只承诺「不翻 Done」）。出错的是读它的人——我按「有魔法词这次合并就不会动卡」操作，而这个版本文档从来没承诺过。

### 机制

实验设计决定了它只观察一个 observable（Done 有没有翻）。但决策者消费实验结论时，拿到的是压缩版：「加了 Y，安全。」压缩丢掉的正是边界——**同一触发事件（PR 合并）上可以挂任意多条自动化规则，实验只排除了其中一条的其中一个效果。**

这与「记『`*` 要加引号』推广不到 `?`」是同一个错误的两个方向：那个是按单点结论记、推广不动；这个是按单点结论记、**推广过头**。共同解法都是**按机制记，不按结论记**。

### 解法

1. **记录实验结论时显式写观测量与边界**：「验证了合并不翻 Done；同触发器的其他状态联动未测」——一句话的成本，读者就不会拿到压缩版；
2. **按机制建模触发器**：「PR 合并」不是一个开关，是一个事件，事件上挂着一组联动。验证「不发生」类结论时，把同触发器可能的其他效应列出来各看一眼，或至少声明没看；
3. **事后防线兜底**：动作完成后**回读受影响对象的完整状态**（本例：卡的 `stateHistory`，秒级时间差就是自动化指纹），而不是只查实验测过的那个字段。这条防线不依赖事前想得全，成本是一次读操作。

## 数据支撑

- 0807 对照实验：两个相隔 15 分钟的 PR，无魔法词者合并后 2.8s 翻 Done，有者不翻；
- 0810 两次复现：带 `Part of` 的 PR 合并后 2.7s 推到 In Review；同日第二次合并再次触发；
- 发现途径正是解法 3：合并后顺手回读卡状态，而不是信「实验说过安全」。

## 适用范围

- **适用于**：一切「做过实验/验证过，所以安全」的判断——issue 自动化、CI 门禁、hook、webhook、部署联动；也适用于写实验结论进文档的时刻（标注观测量边界）；
- **也适用于**：AI 消费人类留下的实验记录——AI 特别容易把文档里的单点结论当作该操作的完整行为模型；
- **不适用于**：实验本来就穷举了触发器全部效应的场景（那时「安全」是真全称）。

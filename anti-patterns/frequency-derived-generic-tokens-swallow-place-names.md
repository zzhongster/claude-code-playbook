# 反模式：按文档频率自动推导"通用词"，把地名和行业词也吞进去

## 一句话结论

公司名去重里"去掉通用词后比较区分词"这一步，如果通用词表是按出现频率自动推导的，高频的**地名**（SUZHOU / SHANGHAI / NINGBO）和**行业词**（RUBBER / ELECTRONICS / SHIPPING）必然越线——而地名恰恰是区分母公司/子公司、同名异地公司的关键信号。结果是"只剩一个品牌词相同"就自动并，错并成片。地名和数字串必须**永不**入通用词，且 T3 级自动并要求去通用词后至少剩 2 个相同的区分词。

## 场景

- 名称级去重，判定档位：T1/T2 规则并、T3 规则+旁证自动并、T4 交 LLM
- `generic_tokens()` 用 `generic_ratio × 名称数` 做阈值（0.0005 × 90 万 = 出现 454 次即通用）
- 调参手册写着"`generic_diff` 占比高说明通用词缺词，往种子表加词"

## 踩坑经历

2026-08-29 企业样本去重 CN 6.25% 试跑（130 万行）。T3 自动并 18,397 对里 77.7% 去掉通用词后只剩 ≤1 个区分词；抽 25 对一半是错并：`SAMSUNG ELECTRONICS` ⟷ `SUZHOU SAMSUNG ELECTRONICS`（母公司 vs 苏州子公司）、`ZHENJIANG HONGYU` ⟷ `ZHEJIANG HONGYU`、`NEPTUNE SHIPPING` ⟷ `NEPTUNE SUPPLY CHAIN TECHNOLOGY SHANGHAI`。自动推导出 2,045 个通用词，含全部城市名和 `000001` 这类数字串。plan 里"加词"的调参方向与证据完全相反——实施者没有照抄手册，而是把证据摆出来要求改算法，这是对的。

同一轮还发现：抽样前缀 `c45` 在 32 位十六进制 id 上是 1/4096（5,158 行）而非计划假设的 2%——**抽样前缀的比例要按 id 的进制算，不能拍脑袋**。

## 正确做法

- 通用词 = 种子表 ∪ 频率推导，但推导结果做减法：地名表（从数据的城市/省份字段 + 企查查 city 推导，进 git）、数字串一律排除；再加绝对上限（前 N 个）并把结果落盘进报告供人审
- T3 自动并硬门槛：去通用词后 ≥2 个相同区分词；只剩 1 个 → 降到 T4 交 LLM；identifier 级旁证可豁免，city 旁证不能（city 本身就是被吞的那类词）
- 调参前先复算：把"待 LLM"对按原始 reason 重算分布，`--no-llm` 不要覆写 reason
- 截断识别别只认"法律形式被切一半"：按分片做名称长度直方图，尖峰长度（35/50/51）就是上游截断位，长度正好等于截断位且末词不完整 → 标 truncated

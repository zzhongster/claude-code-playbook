# 反模式：AI 生成的视觉产物，只读代码验收，从不真渲染

## 一句话结论

让 CC 生成"给人眼看"的产物（设计稿、原型页、报告页），验收判据却全是**可计算量**（数值对不对、变量齐不齐、diff 干不干净），就会漏掉唯一重要的那件事——**它打开长什么样**。渲染一次的成本是一条命令，但没写进判据就没人做。

## 场景

用 CC 照规格生成 HTML/CSS 类的静态视觉产物：设计 token 参考稿、七类状态视觉稿、可点击原型、静态报告页。生成环境常常没有浏览器（甚至没有 node），于是整场验证都靠"读代码 + 算数值"完成，PR 走完、CI 绿灯、卡片 Done，全程没有任何一双眼睛看过渲染结果。

## 发生了什么

某设计系统交付（2026-07-31，CC 生成、走了分支 + PR + 会话归档，流程一条没少）产出 `tokens.reference.css` + `states-reference.html`，供设计稿脱构建、浏览器直开预览。

次日打开，是一页**无样式的纯文字流**。

根因在 CSS 文件头注释的第 6 行：

```css
/* ...
 * 生产里字号/间距/字体走 Tailwind 原语，不是这里的 --font-*/--space-*。
 * ...（还有 8 行说明）
 * 暗色由 .dark 覆盖。 */

:root {
  --color-bg-canvas: 248 250 252;
  ...（共 119 个变量）
}
```

`--font-*` 后面紧跟的 `/` 与前一个 `*` 凑成了 `*/`，**把文件头注释提前闭合**（CSS 注释不能嵌套）。此后 8 行中文说明被当作 CSS 代码，解析器进入错误恢复，连带吞掉整个 `:root {…}` 块——**119 个 token 变量全部未定义**。

现象具有极强的迷惑性：

- `document.styleSheets.length === 2`，外链 sheet 的 `href` 正常、`disabled === false`——**CSS 文件确实加载成功了**，所以一切"资源加载"方向的排查都会扑空
- `display:grid`、`flex`、`position:sticky` 等不依赖变量的声明照常生效，页面**有排版、有分栏**，只是"皮"没了，看起来像样式没写完而不是文件坏了
- 依赖变量的声明（`background:rgb(var(--color-surface))`、`padding:var(--space-4)`）整条失效；`border-color` 失效后退回 `currentColor`，于是按钮反而多出黑框

修复是**一个字符**：把 `*/` 拆开。

## 为什么静态检查全线放行

排查时逐项验过，全部绿灯：

| 检查项 | 结果 |
|---|---|
| CSS 文件是否存在、路径是否正确 | ✅ 同目录，`curl` 200 |
| 文件名隐藏字符（字节级 `repr`） | ✅ 干净 |
| 编码 / BOM | ✅ UTF-8 无 BOM |
| 括号配对（去注释后 `{` vs `}`） | ✅ 2 : 2 |
| 变量交叉比对（HTML 用到的 vs CSS 定义的） | ✅ 119 个齐全 |
| `git diff` 人工审阅 | ✅ 就是一句正常的中文注释 |
| CI | ✅ 绿 |

**注意第 4 项**：用 `re.sub(r'/\*.*?\*/', '', css, flags=re.S)` 去注释再数括号——非贪婪匹配恰好也在 `--font-*/` 处断开，于是"括号配对"这个检查**用与浏览器相同的错误方式解析，得出了一切正常的结论**。检查器和被检查者犯同一个错时，检查等于没做。

唯一暴露它的动作是渲染：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --window-size=1600,1100 --screenshot=out.png "file://<绝对路径>"
```

一条命令、两秒钟，出图即真相。

## 为什么 AI 生成的产物尤其容易中这一枪

`--font-*/--space-*` 这种写法是**模型写注释的高频习惯**：用通配符指代一族 token，再用斜杠并列两族。人手写注释时更倾向写"`--font-` 和 `--space-` 开头的变量"，反而不容易连着敲出 `*/`。

同类高危字符串（都可能出现在 AI 写的 CSS 注释里）：`--font-*/--space-*`、`w-*/h-*`、`*/*` 之类的路径或通配并列、正则片段 `\d*/\d*`。

## 正确做法

1. **判据里写死"附渲染截图"**。视觉产物的完成判据必须有一条是产物**渲染后的样子**，而不只是"文件已入仓""数值对得上"。截图入 PR，评审看图不看 diff。
2. **对原文件跑截图，别对内联版或临时拷贝跑**。外链、相对路径、加载顺序都是被验对象；拷到别处或内联进去再截图，等于把最可能出问题的环节绕开了。
3. **生成环境没有浏览器，不是免验的理由**——是把验证挪到有浏览器的地方的理由。归档里如实写"未现场渲染"，比默认"应该没问题"强得多。
4. **给 CSS/HTML 加一条注释闭合门禁**。状态机扫一遍，报告"注释外出现的 `*/`"，十几行就够，比正则可靠（正则会犯和浏览器一样的错）：

```python
def scan(text):
    """返回注释外出现的 */ 的行号——即提前闭合的证据"""
    hits, i, inc = [], 0, False
    while i < len(text) - 1:
        two = text[i:i+2]
        if not inc and two == '/*': inc = True;  i += 2; continue
        if inc and two == '*/':     inc = False; i += 2; continue
        if not inc and two == '*/':
            hits.append(text[:i].count('\n') + 1); i += 2; continue
        i += 1
    return hits
```

5. **别让检查器和被检查者共用一套错误假设**。验 CSS 用浏览器的解析结果（`getComputedStyle` 读变量），别用自己写的正则。本例中 `getPropertyValue('--color-surface')` 返回空字符串，一步到位。

## 附带教训：临时写的 grep 会漏，漏的部分会被当成结论

同一次排查里，用来找"未定义变量"的提取脚本是 `grep -oE '^\s*--[a-z0-9-]+'`——只匹配**行首**的声明。而目标文件的字阶部分是一行两个声明：

```css
--font-size-base: 0.875rem;  --line-height-base: 1.375rem;   /* 14 / 22 正文默认 */
```

于是 `--line-height-base` 被判成"未定义"，作为一条独立缺陷写进了任务卡评论，事后才更正——它一直好好地定义在那儿。

**为一次性排查写的脚本，它的漏报会直接变成你给别人的结论。** 行级 grep 之前先确认目标文件是不是一行一声明；拿不准就用真解析器（`getComputedStyle`、CSS parser）复核一遍再往外说。

## 适用范围

- **适用于**：AI 生成的一切"给人眼看"的静态产物——设计稿、可点击原型、静态报告、邮件模板、幻灯片导出；尤其是生成环境无浏览器的场景
- **不适用于**：有完整视觉回归测试（截图 diff）的成熟前端项目——那里这条判据已经内建了

# 5xx 之后直接重试——先查状态，写操作可能已经成功了

> 来源：TOUCH 2.0 自动化夜（2026-08-13），gh CLI 对 GitHub API 的三连 502

## 现象

`gh pr create` 返回 `HTTP 502 Bad Gateway`。直接重试，得到 `a pull request already exists`——**第一次其实创建成功了，只是响应在网关处丢了**。同一晚 `gh pr merge` 也两次 502，那两次查证后是真失败。

## 规则

对**写操作**的 5xx/超时，重试前先查目标状态：

```bash
gh pr view N --json state,mergedAt   # 或 gh pr list --head <branch>
```

- 状态已变 → 操作成功，响应丢了，别重试（重试轻则报错，重则重复副作用）；
- 状态未变 → 真失败，可以重试（等一拍再试，网关抖动常成片出现）。

同一个错误码，两种真相，只有读状态能分辨。这是「失败与空值经常静默、或指向错误方向」的镜像面：**成功也会伪装成失败**。

## 顺带

幂等键/唯一约束（分支名、订单号）是这条规则的安全网——上面 502 能安全处理，正因为 PR 以分支名唯一。设计写接口时给客户端留一个能查状态的键，就是给所有调用方这条退路。

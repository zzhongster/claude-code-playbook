# 同会话自审（Same-Session Self-Review）

## 一句话结论

让写代码的那个会话审自己的代码，得到的是辩护不是审查——它带着写码时的全部假设，倾向于与自己刚做的决定保持一致；「自审」必须换干净上下文，否则等于没审。

## 场景

- 写完代码顺口问同一个会话「帮我看看有没有问题」「再检查一遍」；
- 提 PR 前想省一道人审，用当前会话「自查」后就声称验证过了；
- 团队里人人用 CC：作者的 CC 说没问题，审查者的 CC 一读就发现问题——差异不在模型，在上下文。

## 详细说明

机制与人类校对自己刚写的稿子看不出错别字相同：写作上下文里既有「这段为什么这样写」的全部理由，模型对刚做的决定有自一致性偏置，审查会滑向解释与辩护。更隐蔽的是**错误归因也会被上下文带偏**：作者会话把「没看见」解释成「工具看不见」，而不是去复跑验证。

实测（touch2-engine，0811，给 `/pr` 命令加冷审步骤的 PR）：作者会话自查后自认干净的 diff，交给**全新干净上下文的子 agent**（只喂 diff + 完成判据，不喂任何写作过程解释）连审五轮，共抓出 2 红 10 黄，全部是作者会话没看见的，包括：

- 作者自查 grep 尾随 `| head -20`，30 条命中被静默吞掉 10 条，漏改的引用恰在尾巴里（红）；
- 作者给宪法「安」了一句它没说过的原文（伪引文，黄）；
- 归档声称「已挂后续任务」，实际只挂了会话内 chip，外部系统查无此物（红）；
- 作者第一轮的错误归因「grep 模式没罩住」——也是冷审逼着复跑原命令才纠正的。

**同一个模型，换个上下文，就从辩护者变回了审查者。**

## 替代方案

见 pattern [fresh-context-cold-review-before-pr](../patterns/fresh-context-cold-review-before-pr.md)：提 PR 前新开干净上下文冷读 diff，作者对每条发现给处置（改 / 不改+理由），处置记录随 PR 走。

## 适用范围

- 适用于：任何「作者与审查者是同一个 LLM 会话」的场合——代码、文档、配置、归档皆同；
- 不适用于：不能因此取消人审——冷审替代的是「人当第一发现人」，不替代人的裁决与背书（作者对自己的发现有动机偏袒，「不改」项恰恰最该被人看）。

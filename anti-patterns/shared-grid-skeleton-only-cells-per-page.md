# 反模式：共用表格组件只管骨架，单元格长相散在各页，修一张表别的表不跟着变

## 一句话结论

如果设计系统里的 DataGrid 只负责行、键盘、列宽、虚拟滚动，而「名字 + 第二行」「数量 + 副标」「分布条」「短写法时间」这些**单元格长相**由每个页面在自己的列定义里写，那么「照原型对齐表格」就会退化成逐页改，改了 A 表 B 表照旧；连表底提示条这种全站一致的东西，也要每页自己挂、自己挑键，挂漏了就没有。正确顺序：**先把基础组件补全（内建提示条 + 一套标准单元格 + 声明式列定义），再逐页只换组件**，并用机器检查保证页面目录里不再有手写的单元格样式。

## 场景

- 前端按原型做像素对齐，表格类页面十几张（名单、客户、积分明细、团队、任务…）；
- 有一个共用 DataGrid，看起来「表格已经组件化了」；
- 回修按页拆包、并行派给多个会话，每个会话只对自己那几页。

## 踩坑经历（2026-11-25）

前一天派了一个「表格横切包」，把键盘提示条、渠道图标、短写法时间做成了共用组件，合进了 main。第二天负责人在 staging 上看，说「Grid 还是没改」。并排对原型才发现：

- 「找过的」表名字下面没有第二行，「找到」列只写「70 家」而不是「28 家 · 18 家能联系」，分布条是一条细线，时间还是长串带时区——这些都是**那张表自己的列定义**画的，横切包改了组件，但这张表没换过去；
- 键盘提示条组件在，但不是 DataGrid 内建的：17 张用 DataGrid 的表里只有 7 张挂了，挂了的那张也只传了「双击/回车 打开」一个能力，所以原型那整条提示一直出不来；
- 另有 3 张表绕过 DataGrid，直接用底层 table 库自己拼。

负责人一句话点破：「逻辑上应该先把 Grid 基础组件做好，然后只是换组件吧？现在是每页都还单独改 Grid 吗？」——是的。

## 根因

1. **「有共用组件」被当成「已组件化」**：组件只覆盖了行为层，视觉层（单元格）没有收口，于是每页各写一份，原型一改要改 N 处。
2. **全站一致的东西做成了「可选挂件」**：提示条要页面自己挂、自己报能力，默认就是漏。应该由组件按实际开启的能力自动生成。
3. **按页拆包并行**放大了问题：每个执行位只对自己的页，横切的缺口没有人看见；横切包又只改组件不改调用方。
4. 验收是「组件在不在」，不是「每张表在页面上长得对不对」。

## 正确做法

1. 先盘点：哪些表用共用组件、哪些绕过；页面里自写了哪些单元格样式；全站一致的元素（提示条等）是不是内建。
2. 第一刀只动基础组件：
   - 全站一致的东西**内建**，由组件按能力自动生成（提示条按开启的勾选、打开、改列宽、挪列等能力生成键位）；
   - 照原型补一套**标准单元格**（标题 + 副标、数量 + 副标、进度、分布条、时间、渠道、状态、金额 + 编号、行尾菜单），各带单测；
   - 列定义改成**声明式**：页面只写「这列用哪种单元格、取哪个字段」，不写样式类名；
   - 绕过组件的表收进来。
3. 之后逐页只换组件，删掉页面自写的单元格样式。
4. 加机器检查：页面目录（组件库以外）出现手写单元格样式、自挂提示条、自写时间格式化即判红；PR 贴前后计数。
5. 验收以页面为准：每张表在真环境里和原型截图逐项对，不以「组件已存在」为准。

## 判据速查

- 改一个单元格长相，要改几个文件？> 1 就是没收口。
- 全站一致的元素，页面能不能「忘了挂」？能就是做成了挂件。
- 共用组件有了之后，页面目录里还 grep 得到自写的条、自写的时间格式吗？

# 反模式：为了让不变量通过而删掉冲突证据，把"隔离"做成了"隐藏"

## 一句话结论

实体解析里发现一条记录自带互相矛盾的强证据（同一个名称对应两个不同注册号）时，正确动作是**按证据把实体拆开**，让不变量在原始数据上仍然成立；把冲突字段从"证据视图"里剔除、打个 `multi=true` 标记但后续逻辑谁也不看它，只是让校验看不见问题——数据仍然错着，而且校验失去了发现它的能力。

## 场景

- 名称级去重：一个 `standard_name` 聚合了多行，行级字段（注册号、税号、护照号）在名称级被合并成集合
- 不变量要求"同簇同类型 identifier 只能有一个值"
- 某个名称本身就被两家公司使用（英文名撞车在中国企业里很常见）

## 踩坑经历

2026-08-29 企业样本去重实施计划评审。我的第一版处理：S1 阶段发现某名称同类型 identifier 有多个值 → 该类型整体从 evidence 里剔除，写 `ident_multi=true`。评审指出三点：

1. `ident_multi` 没有任何下游逻辑消费——它不是隔离，只是一个没人读的标记
2. I-4 校验读的是过滤后的 evidence，看不见被删掉的 identifier，于是"通过"
3. 计划里的测试甚至明文要求 `r029`（注册号 Z1）和 `r030`（注册号 Z2）必须在同一簇——把违反不变量的结果当成了预期

这正是"改测试让它绿"的变体：不变量被架空了。

## 正确做法

- **拆实体，不删证据**：冲突名称按 `(name, identifier_type, identifier)` 生成不同的名称实体，各自成簇；没有 identifier 的行归入一个 `IDENT_RESIDUAL` 实体——证据不足以判它属于哪家，所以它**只做自身归一，不参与任何合并，不能当代表**，并进报告等人工处理
- **不变量按原始数据校验**：I-4 直接从行表的 `identifier_type / identifier` 聚合，不看任何派生的 evidence 视图
- **标记必须有消费者**：任何 `*_flag` 列，写它的地方要能指出读它的地方（聚类守卫、选举排除、报告）；指不出来就是隐藏
- 测试断言应是"不同注册号的行不在同簇 + I-4 通过"，而不是反过来

## 识别信号

- 处理冲突的代码路径是"从集合里 remove"而不是"split / reject / route to review"
- 校验函数读的是经过清洗的中间表，而原始表里还留着冲突
- 某个布尔标记只在写入处出现一次

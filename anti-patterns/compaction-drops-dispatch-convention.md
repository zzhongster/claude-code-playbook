# 上下文压缩丢了「往哪派活」的约定，协调会话退回默认派法

## 现象

一个长时间运行的协调会话（Claude 当协调位，同时管十几条子会话）原本有一条约定：**写代码的活派到另外两台机器（air、mini）上的 Codex 执行位**，本机的 Claude 会话只负责验收、提交、建 PR。这条约定是几天前在对话里一步步建起来的：装 Node 22、登录 Codex、建裸仓和队列、建测试库。

上下文压缩之后，摘要只记下了「在做什么」，也就是各条线、各张 PR、各项裁定，没记下「活该往哪派」。之后一整天，所有新任务都开成了本机的 Claude 会话：

- 本机负载一直很高（同时 17 条会话），两台执行机闲着；
- 用户发现后问「现在新任务都不再派给 air 和 mini 了吗」，我第一反应把它理解成「app 里的 SSH 连接」，又绕了几轮才从自己的对话记录里翻出原来的做法；
- 同一段时间里，mini 的 IP 变了，air 上执行位用的 Node 目录也不见了，没人发现。

## 根因

- **约定只活在对话里**：它是「怎么做」，不是「做了什么」。压缩摘要偏向记录事实和进度，这类操作约定最容易被摘掉；
- **默认派法顺手**：新开 Claude 会话一步就开好，而执行位要先 ssh、建 worktree、写 prompt，摘掉约定以后，阻力最小的路自动胜出；
- **连接写死了 IP**：约定里记的是 192.168.2.x，机器换了 IP 以后，就算想起来也连不上，看起来像「那两台不能用了」。

## 正确做法

1. **派活约定当场落进持久记忆**（memory 或项目文件），写清三样：派给谁、怎么连、派之前要核什么。不要只留在对话里；
2. **连接写机器名不写 IP**：局域网 Mac 用 `.local` 的 mDNS 名，比如 `xiechaodeMacBook-Air.local`。找不到时用 `dns-sd -B _ssh._tcp local.` 列出局域网里所有能 ssh 的机器，再用 `dns-sd -L "<名字>" _ssh._tcp local.` 解析出主机名；
3. **派之前先体检**：执行器登录状态（比如 `codex login status`）、运行时目录在不在、负载多少。有一台坏了，当场报出来；
4. **用户问「怎么不用 X 了」时，先翻自己的对话记录**，按用户原话的关键词搜 jsonl，再去猜 X 是什么。别先去查 app 里有没有叫 X 的配置。

## 判据

协调会话开新任务之前，先问自己一句：**这件活之前约定过往哪派吗？** 答不出来，就去记忆里查；记忆里也没有，就说明当初没落盘，现在补上。

# 并行联网调研子代理：分章增量落盘 + 主线程按标题取段

## 一句话结论

一份需要"法规准入 + 认证 + 市场竞品 + 客户名单"四类联网调研的长报告，拆成 **4 个并行子代理，每完成一节就追加写入各自的 md**；主线程同时跑结构化数据、预写不依赖联网结果的章节，只用 `grep -n '^## '` 看进度、`sed -n 'a,bp'` 取需要的段。4 路（11–25 分钟、每路 18–27 万 token）全部跑完，没有一路因"无进度"被杀；上一次单路子代理"成稿阶段一次性写"，在 600 秒无进度处被 watchdog 杀掉，只能从它抓下的原文里抢救。

## 场景

- B2B 市场调研 / 尽调 / 竞品报告，章节之间基本独立（法规结论不依赖竞品结论）
- 联网检索是 IO 密集，串行一小时起步
- 子代理中间过程很长，主对话去读它的完整转录会塞爆上下文

## 详细说明

### 派单 prompt 的四个硬要求

1. **目标文件路径写死，要求"每完成一个大类立刻追加写入"**，抓取的原文另存 `pages/`。这是能活过 watchdog 的关键：文件在持续增长，即使中途被杀，已完成的章节也在
2. **返回主对话 ≤250 字摘要**。摘要用于决策，细节一律从文件取
3. **把用户话里自带的前提列为首要核实项**。这次用户说"产品用北斗，有些市场被北斗制裁，要剔除"。prompt 写明"先查清到底存不存在'禁用北斗'的国家清单，不要顺着用户措辞编造制裁名单"，并要求把"禁止接收信号 / 禁止中国造设备 / 禁止政府采购 / 关税"四类分开给结论。结果前提不成立——真正的障碍是美国 FCC Covered List 把外国生产的无人机、路由器、先进机器人设备整类列入。**这一条成了整份报告的第一结论**；如果顺着前提派单，子代理大概率会凑出一份"北斗受限国家名单"
4. **查不到写"未检索到"，禁止编造条款号、日期、价格**；费用类查不到公开价的写"需询价"

### 主线程怎么配合

- 子代理跑的同时，主线程跑贸易数据（结构化工具调用）、写产品画像 / 市场规模 / 执行摘要骨架这类不依赖联网结果的章节
- 看进度：`wc -l 各文件` + `grep -n '^## '`。某节标题出现了，就 `sed -n '262,340p'` 只读那一段，边读边写对应章节
- **不要 tail 子代理的 JSONL 转录**
- 完成通知到了再读摘要，但**摘要里的数字要回文件复算**（见下）

### 子代理的产出也要核

- 客户名单子代理的摘要写"154 家公司，80 家带明文企业邮箱"。主线程解析名单时脚本复算是 **68 家**（80 是邮箱地址数，有的公司两个邮箱）——差点把 80 写进给用户的总结
- 同一个子代理写的"匹配理由"里有 4 条在推"全自主航行 / 无需驾照是最强卖点"，与认证子代理得出的"行业龙头都只敢叫 Assisted、全自主是美国机器人条目的触发词"直接矛盾。**并行子代理之间没有共享结论，交叉矛盾只能主线程收口**

## 数据支撑

| | 印度稀土永磁报告（2026-09-10） | 劭鑫智能路亚艇报告（2026-09-13） |
|---|---|---|
| 联网子代理数 | 1 | 4（法规准入 / 认证 / 市场竞品 / 客户名单） |
| 落盘方式 | 成稿阶段一次性写 | 每完成一节追加 |
| 结果 | 600s 无进度被杀；靠已存的约 30 页抓取原文续写 | 4 路全部完成 |
| 单路耗时 | — | 11.4 / 15.1 / 23.2 / 24.7 分钟 |
| 单路 token | — | 18.1 / 24.0 / 26.9 / 20.7 万 |
| 单路工具调用 | — | 60 / 57 / 68 / 48 次 |
| 产出 | — | 620 / 500 / 655 行 + 154 家客户表；来源 URL 约 120 / 78 / 87 / 241 |

## 适用范围

- 适用于：章节独立的调研、尽调、竞品、合规扫描类报告；每路任务能在一个文件里闭环
- 不适用于：后一节推理强依赖前一节结论的任务（放单对话）；需要全局统一口径的数值计算（放主线程，参考单对话 vs 多 Worker）

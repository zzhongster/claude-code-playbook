# 团队身份映射唯一真源：一个 JSON，所有技能引用

> 来源：TOUCH 2.0 发群/审批自动化（2026-08-14，TOU-345）

## 问题

同一个人在不同系统里最多有**四套名字**：团队常用称呼、法定全名（企微注册名）、GitHub 用户名、Linear 显示名（name 和 @handle 还不一样）。自动化一多，每个技能/会话各存一份映射、各猜各的：实际踩到的现象是另一个会话跑发群命令时「查无此人」，只能发不带强提醒的纯文本。

## 方案

仓库里放一个 `.claude/team-map.json` 作**唯一真源**，每人一条记录：

```json
{ "name": "常用名", "full_name": "企微注册名", "aliases": ["别名"],
  "github": "gh用户名", "linear_name": "Linear名", "linear_display": "handle",
  "wecom_userid": "企微userid" }
```

所有需要跨系统对人的技能**运行时读它**，不在自己文件里存副本。

## 四条纪律（每条都有当场的教训）

1. **文件头登记消费方**：谁在读这个文件、谁持有例外副本，写在 `$comment` 里。例外要显式：GitHub Actions workflow 无 checkout 读不到仓库文件，只能持内联副本——注明「改表必须同步它」，让漂移至少是看得见的；
2. **填表时实拉 API 核对，不凭记忆**：Linear 显示名从 list_users 实拉——果然和会话里的叫法对不上（「小戴」在 Linear 里就叫小戴，全名却是另一个；某人 Linear 名和企微全名还差一个字）；
3. **最小收集**：邮箱能拉到但没有消费方就不收集（要用再加列）；手机号等 PII 禁入仓（真要按手机号 @，放 Secrets）；角色/权限域不放——那有权威源（CODEOWNERS），复制必漂；
4. **强提醒的键要实测**：企微 `mentioned_list` 只认 userid，塞全名静默降级为纯文本——上线前用真实 userid 发一条验证。

## 什么时候值得建

第二个消费方出现的那一刻。第一个自动化内嵌映射无妨；当第二个技能开始复制这张表，就是拆真源的时机——我们是在发群命令（消费方 1）之后做审批通知（消费方 2）时拆的。

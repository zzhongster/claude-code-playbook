# 按模糊名聚合「X 的对手方」时，X 自己会成为 X 的头号对手方——剔同集团行，单列不丢

## 一句话结论

用模糊名匹配一个实体 X（买家、账户、公司），再聚合"X 的对手方"（供应商、客户、转账对象），匹配会把 X 的关联公司一并收进来；关联公司之间的往来记录里，**X 自己**就出现在对手方一侧，还常常是最大的那个。修法不在"从哪个方向算"，在"谁被算进来了"：把对手方表里**像 X 自己**的行剔出结构指标，单列出声，不丢数。

## 场景

- 提单/交易数据上做"某买家的供应商结构"、"某供应商的客户结构"、"某账户的转账对象"
- 实体匹配是模糊的（名称前缀/分词），一次命中多个抬头（集团内不同法人、不同国家分公司）
- 集团内部有调拨：母公司向子公司发货、总部向分部转账

## 详细说明

**失败形态**（trade-agent-data `trade_signals`，2026-09-07 真库）：`buyer="BETTERWARE"` 命中 MEXICO / GUATEMALA / ECUADOR 三个抬头；出口侧记录里 BETTERWARE DE MEXICO 是向关联公司发货的"供应商"，于是 `top1_share_pct = 30.6%` 是买家自己，真实最大外部供应商只有 19.1%，"主供应商更换 / 集中度下降"两个标签随之失真。

**卡面给的三条候选全在"方向"上打转**：只看进口侧、加 `direction` 参数默认进口、剧本层传完整注册名。前两条都砍掉只有出口侧数据的买家的覆盖，第三条治不了工具。先看数据形状才发现根在抬头匹配——修好后 `intra_group` 里冒出第二家 BETTERWARE AMERICA LLC（卡面根本没提），按方向切根本切不干净。

**修法**（纯函数层加一个谓词，调用方构造）：

1. 对手方表在"剔货代 → 按编号合并"**之后**再剔"像 X 自己"的行——同集团判据按"像不像 X"，合并后一家只判一次；放合并前会让同集团两种写法一个被剔一个留下。
2. 判据两路：编号 == X 的编号；或名称归一后与 X 的检索词 / **任一命中抬头**全等，或以其开头且后随词界（`ACMEX` 不算 `ACME`——与项目里 `focus_supplier` 同一条词边界规则）。
3. **剔出的不丢**：本期的单列 `intra_group`（≤5，票数降序），两窗任一出现即 warning「N 家供应商与买家同名或同集团（…），按内部调拨处理，未计入供应商结构与集中度」。份额、集中度、新进/退出、主供应商更换全部只在外部对手方之间算。
4. 对外只加一句业务口径，不改标签词表、不加参数——下游契约零变更。

修完真库数字：外部供应商 18 家，`top1` 27.8%（基期 32.7%），`intra_group` = DE MEXICO 3384 票 + AMERICA LLC 59 票，标签只剩一条真的。

判据一句：**修一个"算错了谁"的问题，先问"谁被算进来了"，再问"从哪个方向算的"。**

## 数据支撑

- 真库探针前后对照：top1 30.6%（买家自己）→ 27.8%（外部）；`intra_group` 两家，其中一家是卡面未知的
- 纯函数层 3 条 + handler 1 条（编号路、词边界路、`ACMEX` 不误伤）+ 集成用例改同口径（`search_trade` 行剔同集团后家数与面板相等、focus 份额一致）全过；对照口径必须同样剔——否则两份桶不是一份

## 适用范围

- 适用于：任何在模糊实体解析之上做的对手方聚合（供应商/客户结构、资金往来图、关联交易）
- 不适用于：实体解析本身精确（按唯一编号）且集团关系已建模的系统——那时直接用集团树过滤，不需要名称启发式；名称启发式只标记不裁决（不要拿它去**合并**主体，那是另一条坑）

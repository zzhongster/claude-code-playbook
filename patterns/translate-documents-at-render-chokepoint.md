# 批量出多语言文档：在排版层的唯一出口做翻译映射，不要重写生成脚本

## 一句话结论

文档是脚本生成的（python-docx 等），要出另一种语言时，不要让 Agent 逐份重写脚本或翻译成品文件。在排版库「所有文字必经」的那一个函数里加钩子：**收集模式**导出全部待译字符串，**替换模式**按 `{原文: 译文}` 映射替换。数据、引用编号、表格结构全部沿用原脚本，翻译的工作和风险被收窄成「校验一张映射表」。

## 场景

- 同一套排版库生成的多份报告（实测 8 份 Word/PDF + 1 份 Excel），其中大量文字由数据拼出来（f-string、聚合结果、自动编号的引用）。
- 目标语言版必须与原文版数字、编号、版式一致；原文版以后还会改。
- 重写脚本的问题：每份要改几百处，数字会被抄错，两份脚本从此漂移。翻译成品 docx 的问题：run 被切碎，版式难保，也无法重新生成。

## 详细说明

### 1. 找到唯一出口，加两种模式

```python
_CJK = re.compile(r"[぀-ヿ㐀-鿿]")   # 只处理含原文语言的字符串
_MODE, _PATH = os.environ.get("REPORT_I18N", ":").split(":", 1)  # collect:路径 / en:路径

def tr(text):
    if not _MODE or not text or not _CJK.search(text):
        return text                     # URL、纯数字、拉丁文名字直接跳过
    if _MODE == "collect":
        _SEEN[text] = 1
        return text
    if text not in _MAP:
        _MISSING[text] = 1              # 缺译不静默，进程退出时打印
        return text
    return _MAP[text]
```

钩子放在每个 run 都要经过的字体设置函数里。生成脚本一行不改，只靠环境变量切换。键是**渲染后的完整字符串**，所以 `f"... {r_ref}"` 里的引用号已经展开，译文必须原样带上，校验时可以逐条比对。

绕过这个函数的文字（实测：目录域的占位提示是直接写 XML 的）要单独过一次 `tr()`。缺译清单会把它们暴露出来，这也是缺译不能静默的原因。

### 2. 跨文档去重后再分批

先对每份文档跑收集模式，全局去重，再按文档分批交给并行子 Agent。共用章节只译一次，术语自然一致。实测 3,044 条、约 8 万字，分 5 路，每路 2～6 分钟。

每路都读同一份术语表：固定译名、人名规则、单位换算示例。品牌和公司名必须写死，否则各路会各译各的。

### 3. 校验脚本是核心，不是附属品

子 Agent 翻完必须跑校验，修到只剩误报：

| 检查 | 抓什么 |
|---|---|
| 缺译 / 多余键 | 键被改动、漏条 |
| 引用号序列 | `[12]` 被改、被丢 |
| 中文计量单位换算 | `2.2 亿美元` 必须能在译文里解析成 2.2e8（`US$220 million`），允许 0.6% 舍入 |
| 其余数字 | 原文的数字在译文里都要出现 |
| 残留原文、全角标点 | 只允许在括号里保留原文（如日文部门名） |

`亿/万` 换算是这类翻译最大的风险：错一位数读起来依然很通顺。校验器的误报也有固定模式：`1.5–2 亿` 这种单位只写一次的区间、`万亿`、`税号,百分比` 被当成千分位粘在一起。让子 Agent 逐条说明为什么是误报，主会话抽查。

### 4. 校验过了还要看版面

下面这些映射表校验全部通过，只有看渲染结果才发现，都在排版层统一修（只在替换模式生效，原文版不受影响）：

- **分段文字粘连**：粗体小标题和正文是两个 run，中文不需要空格，英文变成 `2026-04.The former`。相邻 run 按标点补空格。
- **页眉换行压正文**：长公司名翻译后变长。页眉串单独给短译名。
- **窄列单词被断开**：`Complet-ed`、`disclos-ed`。替换模式下按每列最长单词计算最小列宽，从宽列匀出来。
- **字体回退**：转 PDF 的机器没有文档指定的字体时，保留的原文字符可能被换成手写体。转换前把字体名替换成本机有的字体。

原文版回归也要跑一次，确认钩子没影响它。

## 数据支撑

一次实测（2026-11，8 份报告 + 1 份 Excel 附件）：

- 3,044 条字符串，5 路子 Agent 并行翻译，每路约 12～16 万 token。
- 生成脚本零改动，只改了排版库；引用编号自检全部通过。
- 校验和子 Agent 自查修掉的真实问题包括括号嵌套导致原文残留等；版面问题 3 类，均在排版层一次修完。
- 没有对照组：没有实际跑一遍「重写脚本」的做法做比较，也没有人工逐句通读全部译文。

## 适用范围

- 适用于：文档由脚本生成、文字都经过少数几个排版函数、原文版还会继续迭代的情况。原文改动后只需补译新增字符串。
- 不适用于：只有成品文件没有生成脚本；需要按目标读者重新组织内容（这时该重写，不是翻译）；文字大量散落、没有统一出口的代码。
- 局限：按整串映射，同一字符串只能有一种译法；分段的句子译者看不到前后文，所以要在任务说明里告诉他「部分字符串是句子片段」。
- 验证情况：目前只在一个项目里用过。按本仓库规则 pattern 需两个项目验证，第二个项目用过后补充。

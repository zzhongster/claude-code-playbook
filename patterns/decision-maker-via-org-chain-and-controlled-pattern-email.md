# 模式：找海外买家决策人——先沿组织链找对"谁下单"，再用带对照组的推测邮箱落地

## 一句话结论

联系人库对非洲、中亚等市场的中资或家族型买家基本是空的，网页搜索也只会返回同名的人。这时候换两步走：

1. **沿组织原文找出真正下单的岗位和姓名。** 买家常常不是目的国的那家子公司，而是中国总部的采购部，或者家族集团里的姊妹公司。
2. **按公司公开的邮箱格式推出地址，再拿对照组验证。** 同一批里放反写、近似和明显虚构的地址：它们都判"不可投递"，"可投递"那一条才算数。

两步得到的东西要分开写：邮箱存在是确定的，邮箱归谁是推断。

## 场景

- 要给某个出口商的前 N 名客户补"决策人 + 本人联系方式"，承诺的是"精准决策人"，不是公司总机
- 买家是中资海外子公司（加纳、坦桑尼亚等），或者是南亚裔家族企业
- 联系人库（按域名、公司名、职能、决策层查）都返回 0 条；官网"联系我们"里只有办公室联系人
- 前几轮已经堆了很多"历史岗位""同名候选""通用入口"，客户的反馈是"找不到决策人就等于没用"

## 踩坑经历（2026-10-22，华美冷柜前 10 客户报告，接管 Codex 会话后的第三轮）

**Herocean（泽世集团加纳公司）**

- Codex 前两轮一直盯着加纳：官网加纳办公室联系人、产品登记邮箱、Dragon/OBOR 品牌页。结论始终是"现任采购负责人未闭环"。

  - 2023-07 半年会公众号原文：集团副总裁、商品平台事业部负责人潘敏；
  - 2024-02 官网年度部署会：商品平台事业部总经理"戚总"、采购部总经理"肖总"；
  - 2022-01 一个当地侨团公众号：商品平台部赞比亚国家总戚馨予。

- 邮箱格式从官网办公室页取：`yiqing.wang@`、`jiaying.chen@`，即"名.姓"。推出 `xinyu.qi@herocean.com` 后同批验证：

| xinyu.qi@ | 可投递 | 目标 |
| qi.xinyu@（反写） | 不可投递 | 证明服务器逐个地址判断 |
| xiaoyu.qi@（近似） | 不可投递 | 同上 |

## 正确做法

1. **先判断"谁下单"，再去找人。** 中资海外子公司的工厂采购多在国内总部。家族企业要看姊妹公司：信箱、电话连号、旧官网的"关联企业"页都是线索。在目的国子公司里找采购负责人，往往方向就错了。
2. **组织原文的找法：**
   - 公司官网新闻（年会、部署会、公益活动）可以拿到岗位和姓氏；
   - 公众号原文能补全名，第三方社团、商会公众号也会顺带写出姓名和头衔；
   - 网页搜索不索引公众号正文，要用搜狗微信搜索，再用浏览器打开 `mp.weixin.qq.com` 读 `#js_content`。
3. **政府登记的公开 PDF 胜过付费库。** 承包商登记、行业准入名录这类年度 PDF 常常直接列出董事总经理和手机，而且是挂在本人名下的官方登记。拿信箱、地址、电话去反查，能把家族集团的公司串起来。
4. **推测邮箱必须带对照组，一批验完：**
   - 目标地址；
   - 反写和近似地址各一个；
   - 一个明显虚构的地址；
   - 一两个已知在用的地址。

   **只有反写、近似、虚构的都判不可投递，目标的可投递才算数。** 如果对方是自建邮件服务器，验证一直 pending，就不要列进报告。
5. **顺手复验官网公示的地址。** 它们是最容易被当成"官方确认"的，也最容易过时。
6. **报告里拆成两句写，各自注明来源：**
   - "邮箱存在"是确定的（验证结果）；
   - "邮箱属于某人"、"戚总就是戚馨予"是推断（命名规律加上同姓、同部门的晋升链）。

   如果报告里有"没有猜测邮箱命名规则"之类的方法声明，要同步改成如实描述。

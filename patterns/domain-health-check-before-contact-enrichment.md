# 模式：按名单域名补联系人之前，先做零成本的「域名体检」

## 一句话结论

B2B 名单补联系人（找人、挖邮箱、推测邮箱）的每一层都以「名单上的官网域名」为锚点。**域名本身失效时，后面每一层都注定白跑，调用费照花**。开跑前用 DNS + 首页访问做一次体检，几秒钟跑完全名单，把失效域名分流出去先找真实官网——这一步零成本，却能提前识别出约四分之一的问题户。

## 场景

- 手里有一份「公司名 + 官网域名」的名单（来自爬虫、旧台账、品类归类结果），要批量补关键人邮箱
- 补联系人的手段都按域名查：付费联系人库按域名找员工、邮箱挖掘服务按域名采集、按「名.姓@域名」推测再验证
- 名单不是当天生成的——域名会过期：公司换域名、关店、域名被转卖、当初登记的是子域名或目录页

## 踩坑经历（2026-10-03～04，1,267 家）

全量跑完四层（公开搜索找人 → 付费库核验在职取邮箱 → 付费库按域名找人 → 邮箱挖掘 → 官网/社媒找负责人 + 推测邮箱 + Snov 验证），仍有 667 家不足 2 个邮箱。直到用户拿一家来问「这个能不能推测邮箱」，查下去才发现它名单上的 `.com` 根本没有收信服务器——真实官网是 `.es`，是**搜邮箱时碰巧在第 9 条搜索结果里看到的**。

回头给 667 家统一体检：**164 家（25%）名单域名收不了邮件**；完全挂零的 495 家里占 30%。

| 情况 | 家数 | 例子 |
|---|---|---|
| 登记的是子域名，主域名正常 | 12 | `shop.contigo.de`、`sklep.amefa.pl` |
| 网站跳转到别处 | 9 | 旧品牌域名跳到新域名；或跳到域名转卖站（已关） |
| 网站打不开 | 105 | 换了域名或已关门 |
| 能打开但不收邮件 | 38 | 单店小商户用 gmail |

这些公司在前面四层里每一层都调用过一遍付费接口。

## 做法

**第 1 步：体检（零成本）**

```bash
dig +short MX example.de          # 空，或只有占位值（如 in.mail.broker.）= 不收信
curl -sIL https://example.de      # 能否打开、最终跳到哪个域名
```

再加一条：子域名还原为可注册域名（`shop.x.de` → `x.de`），**两段式后缀不能拆**（`co.uk`、`com.au`、`com.br`、`com.pl`…）。

**第 2 步：按体检结果分流**

| 体检结果 | 处理 |
|---|---|
| 正常 | 照常跑 |
| 子域名，主域名能收信 | 直接换主域名（这次 11 家里 9 家补到 2～3 个邮箱，收益最高） |
| 跳转 | 用落地域名（原站自己设的跳转是强证据）；跳到转卖/停放页 = 疑似已关 |
| 打不开 | 同名换后缀 + 搜「公司名 + 国家」找候选，**必须过严格的身份核对**（见反模式 [凭页面出现公司名就认官网](../anti-patterns/name-on-page-as-official-site-identity.md)） |
| 能打开但不收信 | 域名没错，去商家目录（cylex/hotfrog/黄页）找店铺邮箱 |

**第 3 步：体检结果随交付物输出**

「仍未覆盖」页单列「域名体检」：失效域名和「真找不到人」是两种原因，下游动作完全不同，不能混在一起。

## 关键判断

- **体检应该前移到名单生产阶段**，不是补联系人时的补救。这次下游补救 164 家只多救回 11 家达标——找回新官网的公司多半是小店，换了域名照样找不到人；而如果名单生产时就体检、结果回写源头，后续每个用这份名单的流程都免于白跑。
- **收益来自「省钱」多于「多找到」**：体检本身不会让覆盖率大涨，它的价值是不再对注定失败的公司调用付费接口，并把失败原因说清楚。
- 长期复用的名单要定期复检，域名过期是持续发生的。

## 适用

任何「以域名为锚点」的批量流程：补联系人、邮箱营销名单清洗、企业数据富化、爬官网。名单越旧、小企业占比越高，失效比例越高。

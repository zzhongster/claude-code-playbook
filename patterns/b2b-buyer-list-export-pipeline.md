# 模式：用海关数据导出「可交付的 B2B 买家名单」——分步交付、每层反核、成本按人头算

**来源**：trade-agent-data，2026-09-30。按数据采购方的评估要求，导出叉车行业 1,000 家欧美澳买家，含画像、规模、营收、关键人、邮箱、电话、WhatsApp。全程约 8 小时，第三方成本约 1,424 元。
**配套实验**：[关键人两路来源：公开搜索 + 付费核验](../experiments/2026-09-30-b2b-key-contact-sourcing-search-plus-verify.md)

## 核心原则

1. **分步交付，每步等确认**：找企业并验证 → 规模与营收 → 关键人 → 联系方式。需求方的口径是在看到中间产物之后才冒出来的，比如「品牌方子公司换掉」「员工数用领英」「是不是都在职」。一次跑到底，这些口径全会错过。
2. **每一层匹配都要反向核身份**：官网、领英公司页、领英个人主页、企业库编号，全都会错配，而且错得很安静。只按名称匹配时，领英公司页错配了 94 个（家具厂配到市政府，Adient 配到 Adient 埃及）。
3. **缺失留空、依据落列**：规模、营收、在职、WhatsApp，每一列旁边都写来源和判定依据；查不到就留空，不拿别的值顶替。
4. **回读产物找错**：本次一半的纠错，是生成 Excel 后抽样回读才发现的。例如分国表里冒出 "GO"，暴露了漏掉的数据源；样本行里出现韩国公司，暴露了国家判定用错了字段。

## 管线

| 层 | 做法 | 坑 |
|---|---|---|
| 数据源盘点 | 列出每个目标市场的进口、出口、跨国聚合提单各覆盖哪几年、有哪些字段 | **跨国聚合源要按目的国拆**，别当成一个「国家」 |
| 产品口径 | 6 位 HS 为主，货描**只补没有 HS 的记录**，两条路都抽样看纯度 | 有 HS 的记录再用货描补，补进来的是配件；通用的「车辆大类」描述要排除 |
| 枚举去重 | 按收货人编号精确枚举；同编号合并；同国同官网主域名合并 | 不用近似基数；**不按名称相似度跨编号合并** |
| 买家国家 | 以企业库注册国为准 | 提单目的国会把海外总部当成当地买家 |
| 剔货代 | 名称分强弱两档词表 + 行业码**只剔报关代理** | 按物流大类剔会误删机场、港口、冷库这类终端用户 |
| 剔品牌方 | 品牌词表 + 「供应商与买家同属一个集团」信号 + 人工过 | 海外子公司名字常不带品牌全称（HC = 杭叉、EP = 中力、Big Joe = 诺力），要分几轮补齐 |
| 官网验证 | 能打开、不是停放页、公司核心词出现在域名或标题里 | 社交主页不算官网；建站平台按完整主机名去重 |
| 员工规模 | 领英公司页（定点搜「Company size」）→ 官网 → 邓白氏，和企业库交叉 | 领英常是集团口径，要标注 |
| 营收 | 用企业库同国同行业实测的人均营收推算，给区间 | 库值容差**上宽下严**（资本密集型企业人均营收本来就高）；先抽样核对库值的币种 |
| 关键人 | 公开搜索找人 → 付费履历核验在职 → 搜不到的公司才用付费库按域名找 | 约 23% 过期或错配；泛名、雇主名多一截、跨国子公司员工都要防 |
| 联系方式 | 付费接口按人取 | 每把 key 同时 ≤3 个请求；**临时失败不进缓存** |
| WhatsApp | 第三方检测服务 | 先拿已知答案的号码校准（14/14 通过才全量） |
| 交付 | 说明页写口径、依据、空缺；黑盒扫描；成本单独出报告 | — |

## 成本结构（1,000 家）

- 付费联系人库占 95%：找人 54%、电话 28%、邮箱 12%、在职核验 6%。
- **最大的浪费**是按域名找人时不限职能、按返回人头扣点：返回 11,133 人，只用上 345 人。改成「公开搜索找人 + 核验」，每位联系人的成本从约 2.1 元降到约 0.1 元。

## 副产品：跑一遍真实交付，会顺带暴露线上口径的错

这次顺带发现并上线修复了两处对外口径：

- 企业库营收：文档写「当地币种」，实测约 98% 是美元。
- 邮箱分类：运营商邮箱和拉美邮箱都被判成企业邮箱，已补到 204 个域名。

**做大批量真实交付，本身就是对线上口径的一次全面抽检。** 发现的问题要走正常的 PR 和知会下游的流程，别在交付脚本里悄悄绕过去。

## 适用

外贸客户开发名单、渠道或经销商开发、数据采购评估、竞品客户摸底。换行业时，数据源盘点、产品口径和品牌方词表这三层要重做，其余各层直接复用。

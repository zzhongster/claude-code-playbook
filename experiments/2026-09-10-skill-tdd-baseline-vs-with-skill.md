# 实验：给「记录一条需求」写技能——无技能基线 vs 有技能对照

**日期**：2026-09-10
**项目**：TOUCH 2.0（touch2-engine）— 功能冻结期的需求入池

## 背景

负责人从客户现场带回一条观察：「客户同行的业务员在领英关注了很多公司，她关注的公司大部分就是她的买家，也就是我们客户的潜在客户」，要求「记录这个需求，未来版本可能加」，并要把「加需求」做成一个技能。

按 writing-skills 的铁律（没有失败测试就没有技能），先让一个子会话在**没有**技能的条件下做这件事，记下它怎么做；写技能；再让另一个子会话**带着**技能做一条全新的观察。两轮都是演练模式（禁止写 Linear / 文件 / 分支，允许只读查仓、查 Linear、联网核验）。

## 假设

**H1**：没有技能时，子会话会把转述当事实直接记录，不去核前提。
**H2**：没有技能时，子会话会为了「记一条需求」跑去读实现代码，范围失控。
**H3**：技能能同时纠正 H1、H2，且不靠压缩输出长度换来。

## 实验设计

| 轮 | 输入 | 技能 | 说明 |
|---|---|---|---|
| 基线 | 领英「关注的公司≈买家」那条 | 无 | 主会话在它跑的同时已把这条建成卡（TOU-1110），所以它的「查复发」命中了——**这一格被污染，不计入结论** |
| 对照 | 全新一条（虚构的测试输入，不对应真实客户）：「某户外家具出口商说询盘大多来自某国的园艺 / 五金连锁，能不能把这类连锁都列出来当潜客」 | 有（读 `~/.claude/skills/adding-requirement/SKILL.md` 后执行） | 与基线不是同一条观察，避免对照会话看到基线会话留下的卡 |

主会话自己对第一条观察做的核验（领英 `details/interests` 现取 10 家关注公司；易查云海关数据里该出口商 227 个买家、10 家关注公司 0 命中）是技能「红旗」表里那行实据的来源，不算实验的一臂。

## 数据

| 指标 | 基线（无技能） | 对照（有技能） |
|---|---|---|
| 核了前提吗 | **否**——明确写「只读仓，不新做研究」，转述原样进卡 | **是**——拆成 5 条断言，逐条找一手来源：易查云海关数据（n=13+17）、三家连锁官网 DOM（n=3）、规格分册、合规册；一条标「不可核（客户私有数据）」 |
| 结论定位有没有被核验改写 | 无 | 有：「潜客 = 买家」→「目标账户，其中五金连锁经海关证实为直接买家；园艺连锁提单 0 次」 |
| 读了实现代码吗 | **是**——adapter 七个方法逐个列出、表列名、合规全册 | 否——`packages/**` 一个文件没开，规格只 grep 分册 |
| 工具调用 | 63 | 40 |
| 子会话 token | 211k | 230k |
| 用时 | 6.8 min | 9.1 min |
| 卡面里有样本 URL 吗 | 否（它自己判断出禁区） | 否（技能明文） |
| 顺带发现 | 我卡面两处技术断言不准（source_type 已有 social；adapter 无读档案能力）——**读实现不是全无价值，但那是审卡不是记需求** | 易查云 `destination=au` 直查会被静默路由到别的市场返回 0，「0 是不覆盖不是没人买」 |

## 结论

- H1、H2 都成立：基线两条都犯了，且是同一个子会话——它用读实现填补了「不核前提」留下的工作量。
- H3 成立一半：对照会话核了前提、没读实现；但 **token 与用时都没降**（230k vs 211k，9.1 vs 6.8 min）。技能做的是把预算从「读实现」搬到「核前提」，不是省预算。如果拿 token 当指标，会得出「技能没用」的错结论——**该看的指标是「转述有没有被一手来源核过」**。
- 各臂 n=1、两臂输入不同，只够定性，不能外推「技能让工具调用降 37%」这类数字。

## 可复用的发现

1. **写技能前先跑无技能基线**，而且要看子会话**怎么填时间**：它省掉的那一步（核前提）和它多做的那一步（读实现）往往是同一笔预算。技能的「红旗」表要同时堵两头。
2. **对照臂换一条新输入**：同一条观察跑两遍，第二遍会撞到第一遍留下的卡 / 文件，「查复发」那格就废了。
3. **技能里的实据数字要来自本项目的基线**（0/10、63 次），换项目就换数字；没跑基线就别写。
4. 演练模式（「不许写任何系统，把计划与产物原样输出」）足以测出流程差异，且零副作用；真正需要写入的动作留给主会话。

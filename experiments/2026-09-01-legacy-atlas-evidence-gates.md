# 实验：遗留系统图谱必须同时过“结构门禁”和“运行无副作用门禁”

**日期**：2026-09-01  
**项目**：管家婆财贸双全+ V8.8（Delphi 5 / SQL Server 2000）逆向工程

## 假设

对缺少现代测试、数据库字段大量复用、UI 动态生成的遗留系统，只通读源码并输出文档不足以支撑完整重写；若把冻结源码、实库目录、真实 UI 状态机和可解释副作用统一进确定性图谱，可以得到可量化、可重复、不会把“看起来像”误写成“已经验证”的后续分析底座。

## 实验设计

### 输入

- 三棵历史源码树，按 Phase 0 SHA-256 清单冻结；
- SQL Server 2000 实际账套的只读系统目录；
- Windows 上真实 V8.8 客户端、中间件和 owner-drawn 动态菜单；
- 运行前后数据库快照、进程状态、事件日志和完整性清单。

### 对照

1. **初始静态生成器**：只按路径匹配二进制 DFM 转换，且不区分 Pascal 函数、中间件方法、数据库对象的目标类型。
2. **证据门禁生成器**：同哈希变体复用派生 DFM；按关系类型限制候选；精确关系未闭合即 P1；作用域不足的名称保留 P2；运行校准枚举允许副作用。

### 验收门

- 结构门：选定输入全部登记、Schema/ID/精确引用 P0/P1 为 0；
- 复现门：同一 provenance 连续生成两次，逐文件路径与 SHA-256 一致；
- 运行门：Baseline → LoggedIn → Sampled → Closed → Cleaned，业务数据和数据库定义零变化；
- 封存门：证据清单文件数、路径和哈希一致。

最终图谱包含 66,672 节点、175,432 条关系、91,993 条明确保留的 P2 后续校准项。数据库目录覆盖 331 表、4,075 字段、1,170 存储过程、90 视图、107 函数和 1 触发器。

Windows 五阶段只读校准采集 523 行运行菜单、11 份 UI 树和 7 张截图；业务数据变化 0、业务 identity 变化 0、数据库定义变化 0。系统层出现 5 条可解释事件和 5 个已访问功能的 `UseCount +1`，说明“只读页面”仍会写使用历史，终态不能机械要求全库校验和相等。

证据封存 318 个文件，复核路径差异 0、哈希不匹配 0。单体边文件曾达到 117,449,399 字节；按稳定 ID 每 90,000 行分片后最大核心生成文件为 87,104,500 字节，两轮输出仍字节一致。

## 结论

数据支持假设。真正有效的遗留逆向底座不是“文档很多”，而是四个门同时成立：

1. 静态结构有冻结分母和稳定 ID；
2. 精确与弱推断分级，未知项进入队列而不是被猜掉；
3. 真实 UI 用数据库前后断言证明无业务污染；
4. 生成物和运行证据都能用哈希重放验证。

若只看源码，owner-drawn 菜单的临时 `WM_COMMAND` ID 会被误当业务 ID；若只看运行 UI，又无法覆盖每个函数和字段；若要求“只读前后全库相等”，会把合法的使用历史误报为污染。三类证据必须相互约束。

## 可复用的发现

- 先冻结分母，再谈覆盖率；“解析成功率”没有分母没有意义。
- 运行校准的终态应拆为业务状态、定义状态、identity/高水位和可解释系统历史，分别断言。
- 同内容历史副本可按输入哈希复用派生解析结果，但来源树和路径必须继续保留。
- 动态/歧义引用保留 P2 比强行绑定更有价值；P2 是后续实验队列，不是失败垃圾桶。
- 生成物还要通过发布介质约束；确定性分片优于引入不可见的手工压缩步骤。
- 该实验验证了横向图谱阶段；是否能降低逐模块文档返工率，需在完成至少两个业务模块后继续比较。
